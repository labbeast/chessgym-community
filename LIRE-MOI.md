# ChessGym — guide en français

**v0.1.0-alpha.1 · Première alpha communautaire · Windows avec Python 3.12**

[Installation et présentation en anglais](README.md) · [Notes de version](RELEASE_NOTES.md) · [Historique des versions](CHANGELOG.md) · [Préparation de la version publique](PUBLIC_RELEASE_CHECKLIST.md)

ChessGym réunit ta bibliothèque PGN, ton échiquier d’analyse et tes révisions dans une application locale et open source. Tes données et ta progression sont conservées sur ce PC. Le projet se construit pour les joueurs, avec les joueurs : retours, traductions, essais et contributions sont les bienvenus dans le [guide de contribution](CONTRIBUTING.md).

Cette première préversion sert à utiliser l’application et à recueillir des retours. Elle s’utilise directement sur cet ordinateur, sans compte, mot de passe ni écran de connexion. L’accès depuis le réseau est refusé. Une installation existante conserve son profil, ses bases, ses réglages, ses brouillons et sa progression. Les fonctions et formats pourront encore évoluer pendant la phase alpha; conserve une sauvegarde personnelle vérifiée avant de mettre à jour une installation existante. Linux dispose d’instructions d’installation, mais n’a pas encore été validé par un parcours complet de bout en bout.

Les douze langues proposées couvrent l’ensemble du catalogue de l’interface, y compris l’installation et les réglages avancés. Les exemples pédagogiques inclus conservent leurs commentaires en français et en anglais.

## Installer depuis GitHub

Installe [Python 3.12](https://www.python.org/downloads/) et [Git](https://git-scm.com/downloads/win). Dans PowerShell :

```powershell
git clone https://github.com/labbeast/chessgym-community.git
cd chessgym-community
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Si tu utilises l’archive des sources de cette version, extrais-la puis commence à la commande de création de l’environnement Python, depuis ce dossier.

Lance ensuite **Demarrer ChessGym.cmd**. Stockfish et les autres ressources se choisissent dans l’assistant à la première ouverture. La bibliothèque, les révisions de coups et la lecture fonctionnent sans moteur. Les méthodes d’installation manuelle restent dans le [guide d’installation](README.md#install-on-windows).

Le dépôt contient le code et ses ressources d’interface. Les données personnelles, identifiants, sauvegardes, grandes bases, banque de puzzles, environnements Python et moteurs installés sont exclus. Une installation neuve ouvre une bibliothèque vide. Le code source propre à ChessGym est sous **GNU AGPL version 3 ou ultérieure** (`AGPL-3.0-or-later`), sauf mention contraire dans un fichier ou une notice tierce; le texte intégral figure dans [LICENSE](LICENSE). Il peut être redistribué et modifié selon ces conditions, sans aucune garantie. Les composants tiers conservent leurs licences respectives, détaillées dans [leurs notices](THIRD-PARTY-NOTICES.md). Le logo a été généré avec ChatGPT à partir du prompt du responsable du projet; ses variantes d’icônes ont la même provenance. Ces ressources du projet sont incluses sous AGPL-3.0-or-later dans la mesure où des droits applicables existent.

## Démarrer

1. Double-clique sur **Demarrer ChessGym.cmd**, dans ce dossier. Le navigateur ouvre http://127.0.0.1:8765.
2. Au premier lancement, l’assistant s’ouvre directement : ajoute les exemples et choisis les ressources à installer. Aucun compte ni mot de passe n’est demandé.
3. L’assistant **Réglages → Installation** s’ouvre. Choisis **Ajouter les bases d’exemples** : trois petites bases sont créées sans téléchargement, pour le répertoire, Deviner le coup et la lecture. Les cartes ouvrent directement les activités. Les commentaires pédagogiques originaux sont en français et en anglais, sous [CC0](examples/README.md).
4. Stockfish est présélectionné pour l’analyse et la notation de Deviner le coup. Choisis **Télécharger et configurer** pour l’installer. Maia 3 et les grandes bases restent facultatifs. Tu peux passer et revenir plus tard.
5. Pour tes propres contenus, crée une base dans **Bibliothèque**, puis utilise **Importer PGN**. Ajouter à nouveau les exemples recrée seulement les bases manquantes et conserve tes notes et ta progression.

Fermer le navigateur conserve tes données et laisse le serveur local actif. Pour arrêter le serveur, utilise **Arreter ChessGym.cmd**. Un double-clic sur le lanceur réutilise l’instance déjà démarrée.

Dans **Réglages → Apparence → Taille du texte**, choisis **110 %, 125 % ou 150 %** pour agrandir le texte de toute l’interface, y compris les menus, listes et annotations. Le choix est enregistré dans ChessGym. **100 %** rétablit la taille normale.

## Adapter les performances à l’ordinateur

Dans **Réglages → Performance**, choisis le budget de cœurs logiques, la mémoire cache de Stockfish et le nombre de processus d’importation. Les limites suivent le processeur utilisable et la RAM détectés sur le serveur ChessGym. Le profil **Équilibré (recommandé)** laisse de la capacité aux autres applications; **Économe** et **Personnalisé** restent disponibles. Une réserve d’au moins 2 Gio ou 20 % de la RAM est conservée lorsque la capacité le permet. Si la RAM n’est pas détectée, le cache est limité à 128 Mo. Une configuration restaurée sur un ordinateur plus petit est automatiquement adaptée.

Le budget CPU se partage entre les calculs et les imports; sur une petite machine, les tâches attendent leur tour. La mémoire choisie correspond au cache cumulé des deux moteurs Stockfish, pas à toute la RAM de l’application: Maia, l’interface et les imports en utilisent aussi. Les changements s’appliquent aux prochaines tâches; un moteur déjà chargé ajuste son cache à son prochain calcul.

## Installer les ressources et les actualiser

L’assistant **Réglages → Installation** propose Stockfish, Maia 3 (79M ou le modèle plus léger 5M), la banque complète de puzzles Lichess et les parties de tournois du dernier mois publié sur Lichess. Il télécharge, vérifie et configure les ressources sélectionnées, avec un suivi de progression. Les bases Lichess sont facultatives; la banque de puzzles demande plusieurs Gio libres pour le téléchargement, la préparation et l’indexation. L’espace disponible est vérifié avant l’import.

Les parties proviennent des archives officielles de tournois diffusés sur Lichess. Les énormes archives mensuelles de parties classées ne sont pas téléchargées par cet assistant. Chaque mois de tournois ajouté crée une base de référence et conserve les mois précédents. Les mises à jour des puzzles conservent les identifiants et ton historique, tout en actualisant leurs classements et métadonnées. Une ressource en échec peut être relancée sans perdre celles qui ont réussi.

Deux cartes facultatives proposent **Lumbra OTB Elite — maîtres 2400+** et **Lumbra Gigabase OTB — complète**. Choisis **Télécharger sur Lumbra**, sélectionne l’édition PGN correspondante sur la [page officielle](https://lumbrasgigabase.com/en/download-area-en/) et accepte la licence sur ce site. Dans ChessGym, indique ensuite le chemin du fichier `.7z` ou `.pgn` présent sur le PC ou serveur qui héberge l’application, puis choisis **Importer la base téléchargée**. Depuis un téléphone, le chemin doit donc désigner le fichier sur le serveur. L’import d’une archive `.7z` demande que [7-Zip](https://www.7-zip.org/) soit installé; un PGN déjà extrait peut être importé sans lui.

ChessGym vérifie les fichiers et prépare l’index avec un suivi de progression avant d’ajouter la référence à la bibliothèque. Les sources et archives conservées se trouvent dans `data/resources/lumbra/`. La Gigabase complète peut demander plusieurs heures d’indexation et beaucoup d’espace disque. Si l’import est interrompu, relancer le même fichier reprend le dernier lot enregistré; aucune base partielle n’est publiée. Les verrous brefs de Windows sont réessayés automatiquement. Pour Elite, coche **Utiliser comme référence de maîtres** si tu souhaites la sélectionner pour la comparaison locale avec les maîtres; cette option est décochée au départ.

Ces bases de Michael Jansen sont sous [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/) : attribution et usage non commercial, avec une licence distincte pour un usage commercial. Aucune donnée Lumbra n’est distribuée avec ChessGym. Les nouvelles éditions se téléchargent dans le navigateur puis s’importent de la même manière; les mises à jour automatiques ne téléchargent ni ne remplacent les bases Lumbra.

**Mettre à jour les éléments installés** actualise les ressources reconnues. Tu peux aussi activer **Mettre à jour automatiquement chaque semaine**, puis enregistrer. Cette option est désactivée au départ. Le serveur doit fonctionner; le navigateur peut être fermé. Une échéance manquée est reprise au prochain démarrage du serveur. Stockfish suit les versions stables officielles; Maia suit les modèles et le code validés par la version installée de ChessGym. Une nouvelle révision Maia non validée est signalée dans **Réglages → Moteurs**.

Les anciennes installations de moteurs restent disponibles. Un moteur désactivé reste désactivé, un choix modifié pendant le téléchargement est conservé et l’activation attend la fin d’un bilan de partie en cours. La mise à jour de l’application dispose de ses propres commandes dans le même onglet.

## Mettre ChessGym à jour

Dans **Réglages → Installation → Mise à jour de ChessGym**, utilise **Vérifier les nouvelles versions**, **Préparer la mise à jour**, puis **Redémarrer et mettre à jour**. ChessGym prépare la version publiée et ses dépendances Python dans un environnement séparé, vérifie l’application et crée une sauvegarde personnelle. Au redémarrage, le lanceur conserve une copie finale de la base de données et applique la version. Si celle-ci ne démarre pas correctement, le code, l’environnement et la base de données précédents sont restaurés. Les moteurs et les grandes bases restent conservés.

L’option **Mettre ChessGym à jour automatiquement chaque semaine** est désactivée au départ. Une fois enregistrée, elle prépare les nouvelles versions lorsque le serveur fonctionne. Le redémarrage attend au moins cinq minutes sans activité de l’interface, ainsi que la fin des analyses, imports et sauvegardes. Une version prête est également appliquée au prochain lancement normal. La progression et les erreurs sont visibles dans les réglages.

Ce fonctionnement demande une installation Git depuis le dépôt officiel et le démarrage par le lanceur fourni ou `run.py`. Une copie modifiée localement est préservée : la mise à jour automatique reste suspendue. Une installation depuis une archive des sources ou un serveur lancé directement par Uvicorn nécessite la procédure d’installation habituelle. Seules les nouvelles versions publiées sont suivies; une préversion peut recevoir les préversions suivantes.

## Choisir la langue

**Réglages → Général → Langue** propose le français, l’anglais, l’espagnol, l’allemand, le portugais, l’italien, le russe, le chinois simplifié, le japonais, le coréen, l’arabe et l’hindi. Le choix est enregistré dans ChessGym. L’arabe utilise un affichage de droite à gauche; l’échiquier, la notation et les champs FEN/PGN conservent leur orientation habituelle.

Les traductions sont incluses dans l’application et fonctionnent hors ligne. Changer la langue conserve les noms de tes bases, tes PGN et tes annotations.

## Choisir un exercice

Le menu **Entraînement** regroupe **Mon entraînement**, **Révisions**, **Exercices**, **Lecture** et **Historique**. La page **Exercices** donne accès aux puzzles, à la visualisation à l’aveugle, aux coordonnées, à la couleur des cases, à Deviner le coup et au jeu contre l’ordinateur.

Chaque activité utilise les onglets **Jouer**, **Historique**, **Statistiques** et **Réglages**. L’accueil conserve les choix de départ et un résumé des paramètres actifs. Les filtres personnalisés, variantes d’exercice, options avancées et outils de gestion se trouvent dans **Réglages**. **Enregistrer** applique les changements; **Annuler** conserve les choix précédents. Les records détaillés sont disponibles dans **Statistiques**.

**Révisions** s’ouvre directement sur **Bases à réviser**. **Tout réviser** et **Tout apprendre** lancent les cartes correspondantes de toutes les bases activées, même si la liste est filtrée. Les lancements manuels sont directs, sans fenêtre de préparation. Les objectifs de durée et de quantité sont gérés dans le plan d’entraînement.

## Composer mon programme d’entraînement

Pendant une activité, la barre supérieure affiche son nom, le temps restant ou effectué, la progression et les commandes utiles. **Pause / Reprendre** conserve la position en révision, en lecture et contre l’ordinateur. Les défis chronométrés gardent leurs propres règles sans pause. Sur téléphone, les actions secondaires se trouvent dans **⋯**. La reprise après rechargement respecte le choix déjà défini dans les réglages de démarrage.

Choisis de reprendre pour la journée ou pour la semaine : le compteur et le nombre d’exercices tiennent compte du travail restant pour la période choisie. Les objectifs sont indépendants, par exemple 5 minutes aujourd’hui et 20 minutes cette semaine. Lorsque l’activité ne fournit que du temps déjà enregistré, la barre indique **Restant estimé** et se met à jour avec ces mesures. Les pendules et défis chronométrés conservent leurs règles. Atteindre la durée prévue permet de poursuivre ; **Terminer ce bloc** reste une action explicite.

Ouvre **Entraînement → Mon entraînement**. **Jour et semaine** affiche toujours les dix catégories dans l’ordre des menus : Révisions, Puzzles, Puzzles à l’aveugle, Coordonnées, Couleur des cases, Deviner le coup, Contre l’ordinateur, Lecture, Analyse et Activité personnelle. Les lignes compactes reprennent les icônes des menus. Le temps du jour et celui de la semaine apparaissent côte à côte, même sans programme. Chaque catégorie possède un objectif quotidien et un objectif hebdomadaire modifiables séparément. À zéro, **Sans objectif** remplace le ratio, et le temps continue de s’accumuler. Les panneaux **Objectifs et détails** sont retirés de la liste. Dans **Programme**, un sélecteur commun permet de choisir l’activité pour modifier ses objectifs et retrouver ses blocs, ses ressources et son travail déclaré. Les trois onglets sont, dans l’ordre, **Jour et semaine**, **Programme**, **Statistiques**. La page Bilan séparée est retirée.

Dans **Programme**, pars d’une page vide ou ajoute les blocs d’un modèle. Pour chaque bloc, choisis une activité, une ressource, un objectif hebdomadaire en minutes, séances ou quantité, puis sa priorité. Le budget hebdomadaire est facultatif; la charge et la marge restent des estimations. Enregistre, puis active le programme maintenant ou pour la semaine suivante. Tu peux aussi le conserver comme modèle personnel.

Les révisions et la lecture lancées depuis un bloc utilisent les outils habituels. Le bandeau **Pause**, **Terminer ce bloc** et **Retour au programme** conserve le lien avec ton programme. Une pause garde le travail enregistré sans compter une séance terminée. Évalue la carte en cours avant de terminer un bloc de révision. En lecture, **Confirmer cette partie étudiée** compte la partie une fois dans cet épisode, sans ajouter de durée une seconde fois.

Les puzzles classiques et Storm, Deviner le coup, l’ordinateur, À l’aveugle, Coordonnées et Color peuvent aussi être lancés depuis un bloc. Choisis l’outil ou la base, puis ses paramètres dans le composeur. Le bandeau conserve le contexte après navigation et rechargement; les mesures proviennent des réponses et parties réellement enregistrées. Termine l’exercice ou la partie en cours avant **Terminer ce bloc**. Les chronomètres natifs de Storm, Coordonnées et Color conservent leurs propres règles : revenir au programme ne suspend pas une épreuve chronométrée.

Le travail commencé directement dans un outil et le travail lancé depuis un bloc alimentent automatiquement leur catégorie, même sans objectif ou sans programme. **Travail à attribuer** et ses commandes sont retirés : aucune attribution manuelle n’est nécessaire pour retrouver ton temps. Les objectifs plus précis d’un bloc conservent leurs règles de ressource, de quantité et de fin de séance. Les durées observées permettent de proposer des estimations et des objectifs, avec aperçu avant application. Les modèles personnels permettent de réutiliser des objectifs sans recopier les résultats.

Les colonnes du jour et de la semaine utilisent la même présentation : temps effectué / objectif, barre de progression, essais et séances lorsque ces mesures existent. Les détails des blocs et le travail déclaré restent accessibles dans **Programme**. La vue principale ne contient plus les sections **Autres séances en cours**, **Travail par jour** ou **Préparer une séance**. Les échecs comptent comme du travail. Un essai correspond à une réponse de révision ou de Deviner le coup, un puzzle tenté, un exercice à l’aveugle terminé, ou une réponse dans Coordonnées ou Color. Ces compteurs restent distincts des cartes travaillées, parties terminées et séances explicitement confirmées. La lecture conserve ses minutes et ses parties étudiées sans inventer d’essais. Les anciens compteurs qui ne peuvent pas être établis restent inconnus.

L’analyse sur l’échiquier est suivie automatiquement tant que la page est visible et active. Le suivi s’arrête après 90 secondes sans interaction, quand la fenêtre perd le focus ou avec **Pause**. Une activité de lecture conserve son suivi de lecture, sans compter la même durée en analyse. Les parties de club, les exercices papier et le travail externe se déclarent avec leur date, leur durée et une note facultative. Une déclaration peut être corrigée ou supprimée. Évite de déclarer une durée déjà enregistrée automatiquement.

Dans **Statistiques**, choisis 7, 30, 90 ou 365 jours, ou une période personnalisée, puis un regroupement par jour, semaine ou mois. Les barres empilées montrent les activités au fil du temps; le diagramme circulaire montre leur répartition. Le calendrier coloré et les moyennes par jour de semaine permettent de repérer ton rythme. Les filtres d’activités s’appliquent à tous les graphiques, au temps total, aux jours actifs, à la moyenne quotidienne et à la comparaison avec la période précédente. **Voir les données** ouvre les valeurs détaillées. Les durées inconnues sont signalées à part.

Les objectifs recommencent chaque lundi selon le fuseau et le début de journée d’étude configurés. Une semaine incomplète ne crée pas de dette. Les changements de programme s’appliquent par défaut aux semaines suivantes; tu peux choisir de les appliquer à la semaine courante. Les bilans distinguent temps actif, temps de réponse ou écoulé, et temps déclaré. Les nouvelles réponses et les incréments de lecture comptent à leur date d’enregistrement; une requête reçue tardivement peut donc appartenir à un autre jour d’étude.

Le programme et ses résultats font partie de la sauvegarde personnelle. Dans les réglages de démarrage, **Mon entraînement** peut être choisi comme écran initial de cet appareil.

## Lecture des cours et recueils

Dans les **Réglages de la base**, active **Suivre la lecture de cette base** puis enregistre. Le nouvel onglet **Lecture** regroupe ces bases : progression, parties lues, temps de lecture et temps restant estimé. **Dernier signet** rouvre la dernière partie à son signet; **Continuer la lecture** reprend la partie inachevée ou passe à la suivante. **Parties** ouvre la liste habituelle, avec le pourcentage de chaque partie.

La lecture se fait dans l’échiquier d’analyse. Chaque coup consulté de la ligne principale avance le signet; revenir à un coup précédent ou explorer une variante ne le fait pas reculer. Le drapeau **⚑** repère le signet dans la notation. Pour le déplacer volontairement, fais **clic droit → Déplacer le signet ici** sur un coup de la ligne principale. Sur tablette ou téléphone, utilise un appui prolongé; le menu **⋮** du coup sélectionné offre aussi cette action.

La progression d’une base est pondérée par le nombre de coups de ses parties. Un chapitre sans coups compte comme un diagramme, lu dès son ouverture. Les réglages permettent de **tout marquer comme lu ou non lu**, sans effacer le temps déjà consacré à la lecture. Une copie d’une partie commence non lue; un déplacement conserve son suivi. Modifier une annotation conserve le signet; changer la ligne principale le ramène au dernier coup commun si nécessaire.

Le chronomètre compte le temps actif dans l’analyse, s’arrête lorsque l’onglet est masqué ou la fenêtre perd le focus, et se suspend après 90 secondes sans interaction. L’estimation restante apparaît après un minimum de lecture mesurée; elle est indicative. Signets et progression sont enregistrés sur le serveur et disponibles dans les autres onglets de ChessGym.

## Puzzles à l’aveugle

Le **Temps de visualisation** démarre à l’affichage des coups ou des pièces et se fige lorsque tu cliques sur **Je suis prêt** (ou **Reconstituer la position**). Il reste disponible après un rechargement, figure dans le bilan et entre dans le temps total de l’historique. En mode **Positions**, les pièces sont regroupées par couleur et par type : une icône est suivie de toutes les cases correspondantes.

**Ouvertures** et **Positions** ont chacun une cote personnelle, initialement 500. En exercice classé, la courbe à exposant **1,4** augmente automatiquement la charge de 5 à 50 coups complets, ou de 3 à 32 pièces, entre les cotes 500 et 3000. La sélection utilise une plage autour de la cible; les rois et les pions sont compris. Le niveau tactique Lichess est réglé séparément. La cote est une échelle de progression locale.

**Pour gagner des points, il faut trouver toute la solution sans erreur.** La reconstruction de la position finale reste une statistique secondaire : son pourcentage s’affiche séparément et ne change ni la réussite du puzzle ni la cote. Elle est facultative, même en exercice classé, et peut être passée après la résolution. Révéler ou abandonner avant de terminer la solution compte comme un échec; le faire pendant la reconstruction conserve le résultat du calcul. Une séance commencée reste récupérable en revenant à cet écran; la fermer ne l’abandonne pas. Une même tentative ne compte qu’une fois, et un puzzle déjà commencé dans ce mode se rejoue sans modifier la cote. Le temps ne change pas les points.

Décoche **Exercice classé** pour retrouver les filtres manuels. **Reconstituer une position** conserve l’exercice libre depuis une partie personnelle. Les anciens exercices restent non classés, et les résultats déjà enregistrés sont conservés. Les deux cotes et leurs résultats sont inclus dans les sauvegardes personnelles.

Les puzzles standard et à l’aveugle utilisent le calcul Glicko-2 de Lichess : la cote varie fortement au départ, puis se stabilise à mesure que l’incertitude diminue. Le statut provisoire dépend de cette incertitude, sans nombre fixe de puzzles à terminer. Les cotes et historiques existants sont conservés; les nouvelles mesures d’incertitude démarrent haut pour permettre une recalibration rapide. Les deux modes à l’aveugle gardent leur propre échelle de progression.

## Historique des entraînements

**Entraînement → Historique** regroupe les neuf outils dans un tableau commun. Le bouton ou l’onglet **Historique** de chaque outil présente ce même tableau, limité à l’activité concernée. Tu y retrouves la date, le travail effectué, la durée enregistrée, l’état et le résultat. Selon le mode, les détails ajoutent les points, la précision, les erreurs, les aides, le classement ou la base source.

Les filtres permettent de choisir l’outil, une période, l’état, le résultat et un texte à rechercher. Les dates suivent le fuseau horaire du navigateur. **Détails** montre les réponses enregistrées; les longues listes se chargent par pages. Lorsqu’une partie ou un exercice source existe encore, l’action de consultation permet de le retrouver.

Une ligne conserve son sens propre : **réponse de révision**, **tentative de puzzle**, **séance** de Storm, Deviner le coup, À l’aveugle, Coordonnées ou Color, **partie contre l’ordinateur**, ou **visite de lecture**. Les puzzles d’un Storm sont détaillés dans leur séance et ne sont pas comptés une deuxième fois dans les puzzles classiques. Les anciennes réponses de révision ne sont pas regroupées artificiellement en séances. Le bouton manuel **Maîtrisé** ne créait pas de réponse notée dans cet ancien journal.

La durée correspond à ce qui a réellement été mesuré. Les nouvelles parties contre l’ordinateur et les visites de lecture conservent leur temps actif; les autres exercices gardent leur durée de réponse ou leur temps écoulé. Pour une ancienne partie avec pendule, le temps consommé peut être calculé sans compter l’incrément. Si une ancienne partie sans pendule n’a aucune mesure, **—** indique cette absence, plutôt que d’inclure les heures passées navigateur fermé. Une séance inachevée ne devient pas automatiquement une réussite.

Les visites de lecture sont journalisées à partir de cette version, avec le premier et le dernier coup de la ligne principale enregistrés et le temps actif. Le pourcentage lu de la partie reste une progression globale, distincte du travail de cette seule visite. Les totaux de lecture déjà existants sont conservés, sans inventer leurs anciennes dates de visite. L’historique et le journal de lecture font partie des sauvegardes personnelles; les activités anciennes supprimées ou jamais enregistrées ne peuvent pas être reconstituées.

## Jouer contre l’ordinateur

Dans **Entraînement → Jouer contre l’ordinateur**, choisis Stockfish (force 0 à 20) ou Maia 3 (niveaux humains 600 à 2600), ton camp et la position de départ. Tu peux partir de la position initiale, coller un FEN ou utiliser **⋯ → Jouer cette position** depuis l’analyse. L’analyse d’origine, ses variantes et son curseur sont conservés; les coups joués contre le moteur forment une partie séparée.

**Reprendre le coup** annule ton dernier coup et la réponse adverse. **Rejouer** démarre une nouvelle partie depuis la même position de départ. **Analyser la partie** ouvre ses coups dans un échiquier indépendant; tu peux ensuite l’ouvrir dans l’analyse principale pour l’annoter et la sauvegarder.

Toutes les nouvelles parties sont conservées dans **Historique**, même lorsqu’elles sont encore en cours. Cette liste reste indépendante des bases PGN et de la partie actuellement reprise. Depuis l’historique, utilise **Revoir**, **Analyser**, **Reprendre** ou **Copier dans une base…**. Commencer une nouvelle partie conserve la précédente dans cette liste. La partie courante garde sa position, ses coups, ton camp et les réglages du moteur après une fermeture ou un rechargement du navigateur.

Dans les **Réglages** du mode ordinateur, tu peux activer **Copier automatiquement les parties terminées** et choisir une base personnelle. L’option est désactivée au départ. Elle crée une copie lorsqu’une nouvelle partie se termine, sans reprendre rétroactivement les anciennes parties terminées. Les copies déjà présentes et leurs annotations ne sont jamais écrasées par la suite. Tu peux aussi copier manuellement une partie en cours. Les bases de référence ne sont pas des destinations possibles. Si la copie automatique échoue, la partie reste dans l’historique avec un indicateur à vérifier.

Pour jouer avec une pendule, choisis **Sans limite**, une cadence proposée ou **Personnalisée** avec des minutes par joueur et un incrément en secondes. L’incrément s’ajoute après chaque coup légal. Les pendules se mettent en pause quand tu fermes le navigateur, masques l’onglet ou quittes l’échiquier du mode ordinateur. Au retour, les temps restants sont conservés et restent arrêtés jusqu’à **Reprendre** : le temps passé ailleurs n’est pas déduit. Une perte au temps termine la partie, sauf si l’adversaire ne dispose pas du matériel nécessaire pour mater; le résultat est alors nul. Les copies PGN contiennent la cadence et les temps enregistrés par coup.

Les changements sont d’abord conservés sur l’appareil, puis synchronisés dans ChessGym. Attends la confirmation de synchronisation avant de fermer cet onglet. Le badge de conservation signale un problème de stockage, de synchronisation ou de copie. Une mise à jour concurrente est refusée pour préserver la version la plus récente. Les sauvegardes personnelles incluent l’historique, les pendules et les réglages de copie.

L’historique commence avec cette fonctionnalité. La dernière partie encore conservée par une ancienne version peut y être ajoutée; les anciennes parties remplacées sans sauvegarde ne peuvent pas être reconstituées.

Maia 3 reproduit les choix de joueurs humains; son niveau utilise l’échelle Lichess comme repère, sans équivalence garantie avec ton classement. Le temps par coup règle Stockfish, tandis que Maia 3 utilise son modèle directement. Les calculs se font sur la machine qui héberge ChessGym, y compris quand tu joues sur téléphone. Pour installer Maia 3 sur un autre PC Windows : `.venv\Scripts\python.exe scripts/install_maia.py`. L’installation conserve le moteur et ses modèles dans `engines/maia3/`, avec un environnement séparé. Les parties Maia déjà conservées restent reprenables avec Maia 3, au même niveau et à la même position. Les instructions Linux et les variables de configuration sont dans le [guide d’installation](README.md).

## Gérer les moteurs

Ouvre **Réglages → Moteurs** pour choisir le moteur d’**analyse et jeu classique** et, séparément, le modèle Maia 3 pour le **jeu humain**. Le changement s’applique aux prochains calculs sans redémarrage. Une partie contre l’ordinateur déjà conservée garde sa position et ses réglages et utilise le moteur choisi à sa reprise.

- **Ajouter un moteur** : indique son nom et le chemin absolu de son exécutable sur le PC ou le serveur qui héberge ChessGym. Le moteur doit parler le protocole UCI; ChessGym vérifie qu’il répond et joue un coup légal. Les moteurs sans réglage de force compatible jouent à leur force normale.
- **Tester** vérifie le fonctionnement et actualise la version connue. **Modifier** permet de changer le nom et, pour un moteur externe, son chemin.
- **Retirer…** enlève le moteur de la liste après confirmation, en conservant les fichiers sur le disque. Un moteur actif doit d’abord être remplacé ou son rôle désactivé.
- **Vérifier les mises à jour** consulte les sources officielles. Le catalogue propose Stockfish et Maia 3 en 5M ou 79M. **Installer une version** lance le téléchargement et les vérifications en arrière-plan. Une installation réussie s’ajoute à la liste; sélectionne-la ensuite pour l’utiliser. Les versions précédentes restent disponibles. Une nouvelle révision Maia non encore validée pour ChessGym est signalée sans installation automatique.

Ces réglages sont propres au serveur et communs aux onglets de ChessGym. Le fichier `data/engine-catalog.json` et les fichiers des moteurs ne font pas partie des sauvegardes personnelles; configure-les séparément si tu changes de serveur. Les moteurs déjà présents sont reconnus lors de la création du catalogue. Ensuite, les choix faits dans cet onglet ont priorité sur la détection automatique et les variables d’environnement.

## Bibliothèque et bases

Les dossiers organisent des bases dans une arborescence : les sous-dossiers sont indentés, avec des traits de liaison et un chevron pour déplier ou replier chaque branche. Le nombre à droite indique les bases directement contenues dans ce dossier. Les branches conservent leur état pendant l’utilisation de l’application; la création d’un sous-dossier déplie ses parents. Au clavier, Haut/Bas déplacent le focus, Droite déplie une branche et Gauche la replie ou revient au parent; Entrée sélectionne le dossier. Chaque base contient autant de parties ou de positions que nécessaire. Ses catégories sont libres : ouvertures, finales, tactique, cours, erreurs personnelles…

Dans la bibliothèque, un **clic droit sur une base** ouvre son menu **Réglages de la base**. Un **clic droit sur un dossier** permet de le **Renommer**; ses sous-dossiers et son contenu restent en place. Sur tablette, utilise un appui prolongé. Au clavier, sélectionne la base ou le dossier avec Tab, puis utilise **Maj+F10**; **Échap** ferme le menu. Les vues « Toutes les bases » et « Sans dossier » ne se renomment pas. Un dossier sans base et sans sous-dossier propose aussi **Supprimer le dossier vide** au clic droit et dans la zone centrale lorsqu’il est ouvert. Après confirmation du nom, le contenu est revérifié; un dossier rempli entre-temps est conservé.

**Déplacer et réordonner les bases** : glisse une carte vers un dossier dans l’arborescence, ou vers **Sans dossier** pour la remettre à la racine. Glisse-la avant ou après une autre carte pour changer son ordre. La destination est surlignée et un repère indique la position d’insertion. Sur tablette, utilise la poignée **⠿** de la carte; un clic sur cette poignée ouvre aussi le choix du dossier. Au clavier, **Alt + ↑ / ↓** sur la poignée déplace la base dans l’ordre affiché. L’ordre est enregistré dans la bibliothèque et conservé après fermeture; les vues par dossier gardent cet ordre relatif.

**Logo de la base** : dans **Réglages de la base**, choisis l’une des 12 icônes ou téléverse une image PNG, JPEG ou WebP de 5 Mo maximum. L’aperçu permet de vérifier ton choix avant de cliquer sur **Enregistrer les réglages**. Les images sont adaptées automatiquement au format du logo. L’ordre et les logos font partie de la sauvegarde complète de ChessGym.

Les parties des bases apparaissent par défaut dans l’ordre croissant d’ajout / du PGN; **Mes parties** conserve les plus récentes en premier selon la date de jeu. Les flèches **← / →** accompagnées du compteur **5 / 100** dans l’analyse naviguent entre les parties de la liste ouverte, en conservant son tri et ses filtres. Elles sont distinctes des flèches qui avancent ou reculent d’un coup.

La table présente les blancs et les noirs, leur classement lorsqu’il figure dans le PGN, la date, le résultat, la cadence et le site. Dans **Réglages de la base**, active **Mes parties** pour inclure son contenu dans cette vue transversale. La colonne de gauche sélectionne les parties pour une action de groupe; la colonne **Réviser** indique séparément leur inclusion dans les révisions.

**Gérer les parties et exercices** : coche les éléments voulus à gauche, puis utilise **Inclure aux révisions**, **Exclure**, **Dupliquer…**, **Déplacer…** ou **Supprimer…** dans la barre de sélection. La case d’en-tête sélectionne les résultats actuellement affichés. Les éléments sélectionnés restent sélectionnés lorsque tu changes de filtre; leur nombre, y compris ceux qui sont masqués, reste indiqué. **Désélectionner** vide la sélection.

**Modifier les informations PGN…** permet de modifier les en-têtes d’une ou plusieurs parties sélectionnées. Pour attribuer le même tournoi à cinq parties, sélectionne-les, ouvre ce bouton, choisis **Remplacer** pour **Tournoi / événement**, inscris le nom puis applique la modification. Chaque champ propose **Conserver**, **Remplacer** ou **Effacer**; les champs laissés sur **Conserver** gardent leur valeur propre à chaque partie. Les variantes et annotations sont conservées. Une modification invalide annule tout le lot. L’historique d’édition de chaque partie permet ensuite de l’annuler individuellement depuis son analyse.

Le menu **⋯** de chaque ligne donne accès aux mêmes actions sur cet élément ainsi qu’aux **Informations PGN**. Clique sur un en-tête pour trier dans les deux sens; le menu **Trier par** propose aussi la date d’ajout, la dernière modification et les classements. La recherche accepte les noms, titres et champs PGN; le filtre **Révisions** affiche toutes les entrées, celles incluses ou celles exclues. Les critères restent en place après une opération.

**Recherche avancée** est disponible dans les bases personnelles, **Mes parties** et les grandes bases de référence. Combine joueur, nom, prénom, couleur, adversaires avec les Blancs ou les Noirs, tournoi, lieu, ronde, dates, Elo, résultat, code ECO, ouverture et cadence. **Appliquer les critères** lance la recherche; **Effacer les critères avancés** les retire. La recherche simple et les autres filtres restent combinables. Le tri, les pages et les boutons partie précédente/suivante de l’analyse conservent les critères.

Les mots du nom et du prénom doivent tous appartenir au même joueur, sans imposer leur ordre dans le PGN; accents et majuscules sont ignorés. Les dates de début et de fin sont inclusives. Une date PGN partielle, par exemple `2024.??.??`, correspond à une année : elle est retenue si cette année recoupe la période demandée. Une date complètement inconnue est écartée lorsqu’une période est imposée. La plage Elo peut porter sur les deux joueurs, au moins un joueur, les Blancs ou les Noirs; un classement absent ne satisfait pas une limite chiffrée. ECO accepte `B90`, un préfixe tel que `B9`, ou une plage telle que `B90-B99`.

Dans le contenu d’une base, les onglets **Parties**, **Joueurs** et **Tournois** permettent aussi de parcourir les données. La liste des joueurs indique leurs parties, leur répartition Blancs/Noirs, les Elo minimum et maximum présents dans les PGN et leur période de jeu. La liste des tournois indique le lieu, l’édition, le nombre de parties et de joueurs. Chaque liste propose recherche, tri et pagination. Clique sur un joueur ou un tournoi pour afficher ses parties; passe dans l’autre onglet pour explorer ses tournois ou ses participants. **Effacer la sélection** retire cette restriction.

Ces annuaires décrivent les informations de la base, sans inventer de fiche FIDE : les variantes de casse et d’accent sont regroupées, mais des noms présentés dans un autre ordre ou avec des initiales ne sont pas fusionnés automatiquement. Un tournoi est regroupé par nom, lieu et date d’événement lorsqu’elle est renseignée, sinon par année de partie. Les dates partielles restent affichées telles quelles. Une première préparation peut être nécessaire sur une grande base; les listes sont ensuite conservées dans un cache reconstruisible. Consulter ces vues ne change ni les PGN, ni les cartes, ni l’historique de révision.

**Dupliquer** crée une copie complète dans la même base ou dans une autre. **Déplacer** conserve l’identifiant, le PGN, le point de départ de l’exercice, l’historique d’édition et l’analyse enregistrée. Les cartes suivent les réglages de la destination : l’historique de révision d’origine n’est pas transféré. Les positions d’ouverture déjà apprises dans la destination gardent leur progression. Une inclusion peut être préparée avant d’activer **Inclure cette base dans Révisions**, dans ses réglages.

**Supprimer** demande une confirmation avec le nombre et un aperçu des éléments concernés; cette suppression ne peut pas être annulée. Si une partie supprimée était encore ouverte dans l’analyse, son contenu reste disponible comme analyse libre. Une partie supprimée provenant d’un compte synchronisé peut être téléchargée à nouveau lors d’une prochaine synchronisation; un déplacement conserve sa provenance pour éviter ce retour automatique.

**Importer PGN** conserve les variantes, commentaires, NAG et informations de pendule. Les imports strictement identiques dans une même base sont dédupliqués. Un PGN invalide est refusé entièrement avec une explication : aucune partie de cet import n’est enregistrée. La première version accepte les échecs classiques, jusqu’à 20 Mo et 10 000 parties par import.

Les cours annotés peuvent contenir des **coups nuls pédagogiques** (`Z0`, `--`, `0000` ou `@@@@`) pour montrer ce qui se passerait si un camp laissait passer son tour. ChessGym les conserve dans les variantes et les affiche sous la forme `--`. Ils restent exclus des réponses à réviser et des lignes de répertoire jouables. Ils ne peuvent pas remplacer une réponse à un échec ni rejoindre la ligne principale. Une position légale ainsi illustrée peut toujours servir de diagramme de départ à un nouvel exercice indépendant.

**Exporter PGN** permet de rouvrir le contenu dans ChessBase ou ailleurs. Les échéances de révision restent propres à ChessGym et sont incluses dans la sauvegarde complète.

## Mes parties : synchroniser Chess.com et Lichess

Dans **Mes parties → ⚙ Comptes → Ajouter un compte**, choisis le site, indique ton pseudonyme et sélectionne une base de destination. Tu peux créer **Mes parties** directement dans ce formulaire. La base choisie apparaît automatiquement dans cette vue. Aucun mot de passe ni jeton n’est nécessaire pour télécharger tes parties publiques terminées ; le jeton de l’explorateur Lichess est indépendant.

Clique sur **Synchroniser** pour récupérer les dernières parties de tes comptes actifs. Le réglage initial couvre au maximum **100 parties sur 90 jours**. Dans **Historique et fréquence**, ajuste la période de 1 à 365 jours et la limite de 1 à 500 parties par synchronisation. Si la limite est atteinte, le bilan le signale. Les parties sont dédupliquées dans chaque base : une nouvelle synchronisation ne remplace pas les annotations ajoutées dans ChessGym. Les joueurs, classements, résultats, cadences et pendules disponibles dans les PGN sont conservés. Les variantes d’échecs et les parties en cours ne sont pas importées.

Deux options sont disponibles par compte :

- **Synchroniser automatiquement** : vérifie périodiquement les nouvelles parties tant que le serveur ChessGym est lancé, même si le navigateur est fermé. L’intervalle initial est de 15 minutes, réglable de 15 minutes à 24 heures.
- **Analyser les nouvelles parties avec Stockfish**, activé par défaut pour un nouveau compte : ajoute les nouvelles parties importées à la file d’analyse. Les anciennes parties déjà présentes peuvent être analysées depuis leur échiquier.

L’API publique Chess.com utilise un cache : une partie tout juste terminée peut apparaître avec un délai. Les erreurs de connexion et les limites de requêtes sont affichées ; attends le délai indiqué avant de réessayer.

Si Chess.com annonce un mois dont l’archive est momentanément introuvable, les autres mois sont importés. Le compte affiche **Synchronisation partielle** avec les mois manquants, qui seront retentés lors du prochain passage. Une synchronisation complète efface cet avertissement. Un compte introuvable, un refus d’accès ou une limite de requêtes reste signalé comme une erreur.

La progression apparaît dans **Mes parties**. Les traitements en attente et les dernières opérations sont regroupés dans des sections repliables. **Annuler** interrompt le traitement en conservant les parties déjà importées ; **Réessayer** reprend un traitement annulé ou en erreur. Retirer un compte arrête sa synchronisation et conserve ses parties.

## Analyse et annotations

Sur ordinateur, la barre de navigation compacte est en haut. L’échiquier occupe le centre, les outils et les graphiques se trouvent à gauche, et un panneau compact regroupe **Stockfish** et **Partie & variantes** à droite. L’échiquier s’agrandit selon la largeur et la hauteur disponibles ; les longues listes défilent dans leur panneau sans faire défiler toute la page. Le moteur affiche son score, sa profondeur et ses suites en haut. En dessous, chaque rangée présente le numéro, le coup des Blancs et celui des Noirs ; les variantes s’insèrent à leur point de branchement. Sur mobile, ce panneau vient juste après l’échiquier, puis les outils et les graphiques.

Le score Stockfish apparaît progressivement pendant le calcul. Revenir à une position déjà analysée réaffiche immédiatement son résultat en mémoire ; le bilan enregistré fournit aussi un premier score lorsqu’il est disponible. **En cours**, **En mémoire** et **Enregistré** précisent l’origine du score. **↻** relance explicitement le calcul en conservant le score disponible à l’écran. Changer de coup annule le calcul précédent.

Quand l’analyse en cours atteint une profondeur supérieure à l’évaluation du coup, son score et sa profondeur remplacent ceux utilisés dans la liste et le graphique. À profondeur égale ou inférieure, l’évaluation conservée reste prioritaire. Le résultat est ajouté au coup même sans analyse complète de la partie, sous forme d’annotation `[%eval …]`. Le brouillon récupérable le conserve automatiquement ; **Sauvegarder** l’inscrit dans le PGN de la base.

L’engrenage **⚙** du bandeau Stockfish règle l’analyse de l’échiquier : choisis une **durée par position à partir de 0,1 seconde**, une **profondeur cible positive**, ou **Sans limite**. Il n’y a plus de plafond applicatif de 60 secondes ou de profondeur 30. En mode profondeur, aucun arrêt lié au temps n’est ajouté; la profondeur atteignable dépend du moteur. **Sans limite** poursuit le calcul jusqu’à ce que tu désactives le moteur ou changes de position. Le choix est conservé pour les prochaines positions et les prochaines visites. **Appliquer** relance le calcul courant si le moteur est activé ; les résultats continuent d’apparaître pendant le calcul.

Dans **Affichage → Informations des coups**, choisis **Écart au meilleur coup** (par défaut) ou l’**Évaluation de la position**. La perte est affichée du point de vue du joueur qui vient de jouer : **−0,85** signifie une perte estimée de 0,85 pion; **0,00** signifie aucune perte détectée. L’évaluation de la position conserve le point de vue des Blancs. Les comparaisons utilisent deux évaluations enregistrées compatibles du bilan, ou deux annotations `[%eval …]` du PGN. Leur survol précise les valeurs avant/après, la source, les profondeurs disponibles et le meilleur coup connu. **—** indique une comparaison impossible, notamment lorsque les meilleures évaluations avant et après proviennent de sources différentes. Les mats ont un libellé explicite, par exemple **Mat manqué**.

Le même menu choisit **Temps pris pour ce coup** ou **Temps restant**. Les longues réflexions sont accentuées en violet : plus de **5 % du temps de départ** pour l’accent modéré, plus de **10 %** pour l’accent fort. En 10 minutes, cela correspond à plus de 30 et 60 secondes. Le temps du coup utilise la durée enregistrée ou les pendules du même joueur, avec correction de l’incrément. Une cadence inconnue ne produit pas de pourcentage inventé.

Les erreurs utilisent le barème Lichess : **imprécision** à partir de 5 points de chances de gain estimées perdus, **erreur** à partir de 10, **gaffe** à partir de 15; les mats sont traités séparément. Les deux accents peuvent être activés indépendamment et restent distincts de tes annotations PGN. Les choix sont mémorisés dans chaque profil **Lecture**, **Répertoire** et **Analyse** de ce navigateur.

Les onglets **Explorer**, **Bilan** et **Répertoire**, dans la colonne gauche, donnent accès aux autres outils. **Bilan** apparaît pour les parties sauvegardées. Les notes et symboles se trouvent dans le panneau repliable **Commentaire / annotations**, directement sous la liste des coups. Son en-tête indique le coup sélectionné. Le menu du clic droit **Commenter / annoter** ouvre ce panneau sans changer l’outil affiché à gauche. Le panneau reste ouvert quand tu navigues entre les coups ; **Appliquer l’annotation** ajoute tes modifications au brouillon. **Sauvegarder** les inscrit ensuite dans la partie enregistrée. Les boutons **＋ Exercice**, **↶ / ↷** et **⋮** restent accessibles en bas.

**Échiquier d’analyse** ouvre la position initiale. Déplace une pièce par glisser-déposer avec la souris ou le doigt, ou clique sur une pièce puis sur sa case d’arrivée. Un dépôt hors du plateau ou sur une case illégale annule le déplacement ; une promotion te laisse choisir la pièce. **Coller PGN / FEN** ouvre une partie ou un diagramme. **Éditer la position** permet de placer les pièces, choisir le trait et les droits de roque.

- Les boutons **|‹ ‹ › ›|** naviguent dans la partie. Au clavier, **←** revient au coup précédent et **→** avance. **↑ / ↓** choisit directement une alternative au coup affiché, ligne principale comprise, sans devoir revenir en arrière ni déplacer les pièces; le coup choisi est encadré, puis **→** entre dans cette variante. S’il n’y a pas d’alternative au coup actuel, **↑ / ↓** choisit parmi ses continuations lorsqu’elles sont multiples. Sans embranchement, **↑ / ↓** reste disponible pour faire défiler la lecture. Le coup rejoint remonte en haut de la liste pour laisser ses annotations visibles. Ces raccourcis restent inactifs pendant la saisie de texte ou dans les réglages. **⇅** retourne l’échiquier. **Copier FEN** copie la position affichée, depuis tous les échiquiers.
- Le menu **Affichage** permet de masquer la colonne des outils et graphiques, de réduire l’échiquier et de régler les annotations avec **A− / A+** (11 à 18 px, 13 px par défaut). Les choix sont conservés dans ce navigateur. Les commentaires du coup actuel restent mis en évidence; modifier la disposition conserve la position, les variantes et les annotations en cours. **Réinitialiser** rétablit l’affichage par défaut.
- Jouer un autre coup crée une variante dans le brouillon uniquement, même pour une partie déjà enregistrée. Les coups joués sur l’échiquier, depuis Stockfish ou depuis l’explorer, ainsi que les annotations et les modifications de variantes, attendent un clic explicite sur **Sauvegarder** avant de modifier le PGN de la base.
- **Sauvegarder** met à jour directement la partie ou l’exercice ouvert, y compris le commentaire et les symboles en cours de saisie. Le point de départ de l’exercice reste inchangé lorsque tu navigues dans les coups. **Enregistrer sous…** crée une copie dans la base choisie. Pour une analyse libre, **Sauvegarder…** demande d’abord la base et le titre.
- **PGN**, dans le panneau Partie & variantes, ou le crayon de la table, modifie les joueurs, Elo, événement, date, résultat, cadence et autres champs. Les variantes et annotations restent conservées.
- Un **clic droit sur un coup** ouvre le menu pour supprimer la suite, monter ou descendre sa variante, la promouvoir localement ou en ligne principale, et annoter. Sur tablette, utilise un appui long ou le bouton **⋮** du coup sélectionné. Au clavier : **Maj + F10** sur un coup.
- **Annuler / Rétablir** conserve les 100 dernières modifications de chaque partie enregistrée, même après fermeture. Pour une analyse libre, l’historique dure pendant la session d’analyse. Les résultats et échéances de révision ne sont pas annulés.
- **Annotation du coup** ajoute un commentaire et les symboles !, ?, !!, ??, !?, ?!, =, +/=, =/+, +/−, −/+, +−, −+.
- **Stockfish** active une véritable analyse à pleine force, avec trois suites possibles et des flèches grises de transparence différente. **Flèches** choisit combien en afficher. Les évaluations sont données du point de vue des blancs.
- Survole un coup de la variante Stockfish (ou donne-lui le focus au clavier) pour voir la position correspondante avec des pièces transparentes. Quitter la ligne rétablit la position courante ; passer entre deux coups conserve un aperçu continu. Cliquer joue toute la suite jusqu’à ce coup et l’ajoute à l’arbre, sans écraser les autres variantes. Pendant une révision, une copie d’analyse s’ouvre et la tentative est marquée assistée.
- Sous les outils à gauche, les onglets **Évaluation** et **Temps des coups** affichent les graphiques de la ligne principale. Clique ou touche un point pour rejoindre le coup correspondant ; au clavier, les flèches parcourent le graphique lorsqu’il a le focus. Une variante affichée sur l’échiquier est signalée séparément.
- **Évaluation** utilise les évaluations les plus profondes du bilan Stockfish ou des annotations des coups, y compris celles de l’analyse en cours. Elle peut donc se remplir sans analyse complète de la partie. Les Blancs sont en haut, les Noirs en bas. La courbe est limitée visuellement à ±5 pions ; l’infobulle conserve le score exact ou le mat annoncé. Une position non analysée reste un trou dans la courbe.
- **Temps des coups** montre les temps de réflexion en barres (Blancs en haut, Noirs en bas) et les horloges restantes en courbes. Le survol donne les valeurs exactes. Les données absentes ne sont pas remplacées par zéro ; les cadences complexes ne sont pas estimées, mais un temps explicitement fourni dans le PGN reste affiché.
- **＋ Exercice** ouvre un éditeur indépendant à partir de la position courante. Tu peux construire sa solution sans modifier la partie ouverte.

### Brouillons et reprise du travail

Le menu **Échiquier / Board** affiche l’analyse actuellement ouverte, **Nouvelle analyse** et les **20 derniers échiquiers ouverts**. Chaque ligne indique le titre, la base, la position dans la liste quand elle est connue, les modifications non enregistrées et la date relative d’ouverture. Une nouvelle analyse conserve le travail précédent dans les récents; la reprise retrouve sa position et ses annotations en cours de saisie. Sur une ligne de brouillon, le **clic droit**, **Maj + F10** ou le bouton **⋯** donnent accès à **Renommer le brouillon…** et **Supprimer le brouillon…**. Le nom personnalisé sert uniquement à retrouver le brouillon : il ne renomme pas la partie dans sa base. La suppression demande confirmation, retire le brouillon et ses annotations non enregistrées, puis retrouve la partie source si elle est ouverte. Elle ne supprime aucune partie de la bibliothèque. **Gérer les brouillons…** reste disponible. Les récents et les noms de brouillons sont propres à l’espace local.

Sur mobile, **Bibliothèque**, **Entraînement** et **Échiquier** sont trois menus déroulants directement accessibles dans la barre du haut. Chaque bouton affiche seulement son icône au repos, puis son icône et son nom quand il est ouvert. Un seul menu est ouvert à la fois; toucher en dehors ou appuyer sur Échap le referme. Les menus partagent les mêmes sections, séparateurs et styles sur mobile et ordinateur.

Les commentaires et symboles en cours de saisie sont conservés **par partie et par position**. Tu peux changer de coup, consulter une autre partie ou changer de section sans devoir enregistrer chaque annotation immédiatement. Ces brouillons restent distincts du PGN de la base : **Appliquer l’annotation** actualise le brouillon, tandis que **Sauvegarder** inscrit l’ensemble des modifications dans la partie. **Enregistrer sous…** crée une copie. Quitter l’analyse, ouvrir une autre partie ou retourner à la révision ne déclenche aucune sauvegarde du PGN original.

L’indicateur de l’analyse distingue **Enregistré**, **Brouillon · cet appareil**, **Brouillon · synchronisé**, un conflit ou une sauvegarde à vérifier. Les changements sont d’abord conservés dans le navigateur, puis synchronisés dans ChessGym après un court délai lorsque le serveur prend cette fonction en charge. Avant de fermer le navigateur, attends la confirmation de synchronisation. Une indisponibilité du réseau ou une limite de stockage est signalée ; un contenu encore uniquement en mémoire ne doit pas être considéré comme sauvegardé.

Clique sur cet indicateur pour ouvrir **Travail conservé** : tu peux reprendre la dernière analyse, la séance de révision ou les autres brouillons disponibles. La reprise est aussi proposée à l’ouverture. Une analyse libre conserve son arbre complet et la position consultée. La reprise d’une séance conserve son ordre, l’exercice courant, les erreurs et les aides ; les exercices supprimés ou modifiés sont revérifiés. Une réponse dont la confirmation réseau a été perdue peut être vérifiée avec son identifiant d’origine, sans enregistrer une deuxième note.

Si deux fenêtres ont modifié le même brouillon, ChessGym conserve les deux versions jusqu’à ton choix explicite : **Garder celle du serveur** ou **Garder celle de cet appareil**. Une partie enregistrée utilise aussi une vérification de version : si elle a changé depuis son ouverture, l’enregistrement est refusé au lieu d’écraser cette modification. Ton brouillon reste disponible pour créer une copie ou recharger la partie. Les sauvegardes automatiques provenant d’une ancienne fenêtre sont bloquées côté serveur : recharge chaque fenêtre de ChessGym pour utiliser la sauvegarde manuelle.

Le stockage de travail local est borné à **128 éléments**, **2 Mio par élément** et **16 Mio au total**. Aucun brouillon n’est supprimé automatiquement pour faire de la place. Enregistrer les analyses dans leurs bases permet de conserver le travail dans les PGN et de libérer les brouillons associés. Les fichiers PGN exportés ne contiennent pas les brouillons encore séparés ; la sauvegarde personnelle, elle, les inclut.

Les boutons **Précédent / Suivant du navigateur** retrouvent les sections et les parties sauvegardées visitées. Ils ne créent pas une étape d’historique pour chaque coup : les flèches de l’échiquier continuent de parcourir la partie. Une navigation impossible pendant une opération en cours conserve l’écran actuel.

### Retrouver une position dans la bibliothèque

L’onglet **Position**, à côté d’**Explorer** dans les outils d’analyse, recherche automatiquement la position affichée dans toutes les bases. Il inclut les positions de départ, les lignes principales et les variantes, même si les coups ont été joués dans un autre ordre. Le trait, les droits de roque et la prise en passant légale doivent correspondre; les compteurs de coups ne changent pas la correspondance.

Il affiche d’abord les **bases contenant cette position**, avec le nombre de parties et d’occurrences. Clique sur une base pour voir ses parties dans une liste compacte : joueurs et classements, résultat et date lorsqu’ils figurent dans le PGN. Un clic sur une partie l’ouvre directement à la position trouvée; les occurrences supplémentaires et les variantes restent accessibles. **← Bases** revient à la liste, et **Afficher la suite** charge les résultats suivants de la base choisie. Les grandes bases de référence recherchent leur ligne principale; un import incomplet est signalé.

Dans chaque base, les parties apparaissent **de la plus récente à la plus ancienne**, d’après la date du PGN (`Date`, puis `UTCDate` si nécessaire). Les parties sans année connue viennent à la fin. Les dates partielles restent regroupées dans leur année et leur mois; à date égale, la dernière partie ajoutée apparaît en premier. Ce tri s’applique aussi aux pages suivantes.

Chaque résultat indique **dossier / base**, le titre de la partie ou de l’exercice et les coups où la position apparaît. Clique sur un coup pour ouvrir le PGN complet à cet endroit; **Var.** indique une variante. Une annotation en cours sur une partie sauvegardée est conservée avant ce changement. Une analyse libre non sauvegardée demande confirmation avant remplacement.

La recherche reste locale et n’utilise pas Lichess. Le cache est préparé à la première recherche et actualisé quand les PGN changent. **↻** permet de relancer la recherche, et **Afficher la suite** donne accès aux résultats suivants. Consulter la liste ne change ni le statut Nouveau ni la progression des révisions. Si certaines parties ne peuvent pas être vérifiées, le résultat est explicitement marqué comme partiel.

## Du bilan Stockfish aux exercices

Ouvre une partie sauvegardée, puis clique sur **Bilan → Analyser**. Le calcul se poursuit en arrière-plan : tu peux naviguer dans la bibliothèque ou continuer une autre analyse. **⚙** choisit une durée libre par position à partir de 0,1 seconde, ou une profondeur cible positive. La valeur initiale reste environ 0,4 seconde par position. En mode profondeur, aucun plafond de durée n’est ajouté; les anciens réglages combinant durée et profondeur restent lisibles. Tu peux annuler le bilan pendant le calcul.

Le bilan présente une **vue d’ensemble visuelle**, une frise des moments importants et une sélection des positions à travailler en priorité. **Tous les moments** permet de retrouver les autres coups signalés. La gravité tient compte de l’évolution indicative des chances de résultat : perdre un avantage décisif n’a pas le même poids que passer d’une position déjà gagnante à une autre position gagnante. Ce classement utilise le même barème Lichess que la liste des coups et reste indicatif, sans note de précision inventée. Les anciens bilans sont reclassés à partir des évaluations conservées, sans nouvelle analyse moteur. **Vérifier** approfondit uniquement le moment sélectionné et met à jour le bilan enregistré, sans toucher au PGN. Un bilan incomplet reste clairement signalé.

Les moments marqués **Revu**, les solutions consultées, les indices et les résultats des essais sont conservés dans ChessGym pour cette version de la ligne principale. Ils survivent à la fermeture et au rechargement; ils font partie des sauvegardes personnelles. Le bilan signale une sauvegarde en attente ou une erreur. Si deux onglets modifient le même moment, choisis explicitement le suivi à conserver. **Effacer le suivi de ce moment** permet de recommencer; une ligne principale modifiée possède son propre suivi.

Par défaut, le bilan porte sur **Mes coups** lorsque ChessGym reconnaît ton pseudonyme parmi les comptes du site concerné, configurés dans **Mes parties → ⚙ Comptes**. Tu peux changer de camp ou consulter les deux joueurs. Les graphiques conservent les coups des deux camps pour montrer l’évolution complète de la partie.

La carte **Répertoire** compare la ligne principale à ton répertoire du même camp, même sans analyse Stockfish. Elle distingue ton écart, une réponse adverse non préparée et la fin normale d’une ligne connue. Le sélecteur permet de comparer à un autre répertoire. Une transposition ultérieure est signalée sans effacer la première sortie. **Voir la sortie** positionne l’échiquier au coup concerné; le raccourci pour compléter un répertoire principal ouvre son outil habituel, où tout ajout reste volontaire.

**Réessayer** propose la position avant l’erreur dans un échiquier temporaire. La notation, le moteur et les graphiques sont masqués pendant la recherche. Tu peux demander un indice, proposer un autre coup ou révéler la solution. Un coup différent de la variante principale peut être accepté si la vérification Stockfish le juge équivalent. Après la tentative, compare le coup joué et une meilleure suite, puis explore librement leurs variantes. **Retour à la partie** retrouve ton analyse, sa position et tes annotations en cours. Ces essais ne sont jamais ajoutés à la partie ni à son brouillon.

Sur un moment du bilan, **Créer un exercice** ouvre un échiquier indépendant à la position avant le coup signalé. La solution est vide au départ : joue toi-même les coups, par clic ou glisser-déposer. Reviens à une position précédente et joue un autre coup pour créer une variante. Les flèches du clavier naviguent dans cet exercice pendant que sa fenêtre est ouverte. Aucun coup Stockfish n’est inséré automatiquement.

Tu peux ajouter des commentaires et des annotations, annuler ou rétablir tes modifications et utiliser le clic droit sur un coup pour supprimer ou promouvoir une variante. Toutes les variantes enregistrées font partie des solutions acceptées pour une position à résoudre. **Stockfish** est disponible à la demande dans la fenêtre ; ses aperçus et ses coups restent dans le brouillon de l’exercice.

Choisis la base et le titre, puis **Créer l’exercice**. La position de départ, les coups et les annotations sont enregistrés dans une nouvelle fiche. La partie d’origine, ses variantes, son historique, la position consultée et les commentaires encore en cours de rédaction derrière la fenêtre sont conservés. **Annuler** ferme le brouillon sans modifier cette analyse.

L’option **Créer « Mes erreurs »** prépare une base avec les révisions activées, le type **Résoudre une position** et la validation **Hybride**. Avec une base existante, ses réglages restent applicables : active les révisions dans cette base au besoin. L’exercice apparaît ensuite dans **Révisions** avec l’espacement habituel. Un exercice créé depuis le bilan conserve son lien avec le coup de la partie source. Le bilan indique les exercices déjà créés et permet de les rouvrir; une répétition de la même création est dédupliquée. Pour modifier une fiche existante, ouvre-la depuis sa base.

L’analyse de l’échiquier n’attend plus les longues analyses de l’explorateur ou du bilan. Les calculs de l’explorateur se suspendent lorsque son onglet est masqué et reprennent à la position affichée lorsque tu le rouvres. Les bilans de parties continuent en arrière-plan.

## Explorateur d’ouvertures

L’explorateur apparaît dans la colonne gauche, au-dessus des graphiques, dans l’échiquier d’analyse et les parties ouvertes. Chaque ligne présente le coup, sa fréquence et son nombre de parties, les résultats **Blancs / nulles / Noirs**, le **pourcentage joué par les maîtres** et l’**évaluation Stockfish**. Un clic joue le coup dans le brouillon et actualise les statistiques. Le PGN de la base ne change qu’après un clic sur **Sauvegarder**.

La colonne **Éval.** se remplit progressivement pour chaque coup affiché, y compris les coups moins fréquents. **+** favorise les Blancs, **−** favorise les Noirs, et **#** indique un mat annoncé. La profondeur réellement atteinte est indiquée au survol. Le bouton d’évaluation de l’explorateur permet de suspendre ou reprendre le calcul. Les scores restent en mémoire sur le serveur pour accélérer un retour à la même position. Changer de position arrête les calculs précédents.

Dans **Explorateur → ⚙ → Analyse Stockfish**, conserve le mode **Rapide** (environ 250 ms par coup) ou choisis une **Profondeur cible** entière positive. Une profondeur plus élevée laisse le moteur explorer davantage, mais prend plus de temps; aucun plafond de 10 secondes n’est ajouté. La profondeur atteignable dépend du moteur. Si la cible n’est pas atteinte, le score porte le signe **≈** et l’infobulle précise les profondeurs demandée et obtenue. Le choix est enregistré dans tes réglages. Changer la profondeur recalcule les évaluations avec cette nouvelle cible, sans réutiliser un résultat calculé avec un autre réglage.

Le bouton **⚙** regroupe les réglages, conservés dans ChessGym :

- **Joueurs Lichess** : sélection de cadences et de tranches de classement. Le point de départ est Rapide, moyenne des deux joueurs entre **1600 et 1999 Lichess**. Il n’y a pas de conversion automatique depuis Chess.com.
- **Mes bases PGN** : une ou plusieurs bases d’étude ou grandes bases importées, dont Mega Database. Tu peux choisir plusieurs cadences et un classement minimum et/ou maximum. Les bornes incluent leurs valeurs et doivent être respectées par **les deux joueurs**. Les transpositions sont reconnues, avec le trait, les droits de roque et la prise en passant. Seuls les coups de la ligne principale sont comptés, une fois par partie et par position ; les copies admissibles d’une même partie sont dédupliquées.
- **Cadences locales** : aucune sélection inclut toutes les cadences. **Inconnue** sélectionne une cadence non renseignée ou non reconnue dans le PGN ; certains exports ChessBase ne fournissent pas cette information. Un classement absent est exclu si une borne Elo est définie ; une cadence inconnue n’est jamais supposée classique. Les Elo des PGN restent distincts des tranches de classement Lichess.
- **Maîtres Lichess** : la base distante des maîtres peut aussi être la source principale, mais son API ne propose aucun filtre de cadence ou de classement. Utilise une base de maîtres importée pour appliquer ces filtres.
- **Référence dans chaque ligne** : maîtres Lichess, joueurs Lichess, bases locales choisies ou aucune comparaison. Les filtres de cette section sont indépendants de ceux de la base principale. Tu peux ainsi comparer Lichess rapide 1800–1999 à Mega Database avec deux joueurs classés au moins 2400. Avec une référence locale ou un second profil Lichess, la colonne porte le nom **Réf.** : ces joueurs ne sont pas automatiquement des maîtres.

Les résultats inconnus contribuent à la fréquence des coups, mais pas à la barre de victoires/nulles/défaites. Les pourcentages de résultats restent toujours orientés Blancs/Noirs, même après avoir retourné l’échiquier. Une position présente seulement en fin de partie n’ajoute aucun coup. Une statistique indisponible est indiquée par un tiret, jamais par un faux zéro.

Pendant l’importation d’une grande référence, les premières positions peuvent afficher les fréquences exactes des parties déjà importées avant que les résultats Blancs/nulles/Noirs soient disponibles. Ce calcul rapide s’applique à une seule référence sans filtre supplémentaire ni doublons à exclure; les résultats indisponibles sont signalés. Après la fin de l’import et la préparation des index, les statistiques complètes sont utilisées automatiquement.

### Probabilité de rencontrer la position

Choisis **Blancs** ou **Noirs** directement dans l’explorer pour indiquer le camp de ton répertoire. La probabilité affichée en pourcentage et en **1 sur N** estime la fréquence de la branche consultée si tu joues les coups de ce camp. Seules les réponses adverses sont multipliées : par exemple, 20 % puis 10 % donnent 2 %, soit environ 1 partie sur 50. Tes propres coups comptent pour 100 %, même s’ils sont rares dans la base.

Le calcul utilise la source principale et les filtres de l’explorer, pas la référence des maîtres. Il suit la branche exacte consultée, sans additionner les autres chemins qui pourraient mener à la même position. Une analyse commençant par un FEN donne une probabilité depuis ce diagramme. Si une réponse manque dans les statistiques, le résultat est indiqué comme indisponible plutôt qu’inventé. L’affichage peut être masqué dans les réglages de l’explorer.

### Connecter les données Lichess

L’API de l’explorateur Lichess demande désormais une authentification. Dans **Explorateur → ⚙ → Connexion Lichess**, ouvre le lien de création d’un jeton, nomme-le ChessGym et ne coche aucune permission supplémentaire. Colle le jeton dans le champ prévu puis enregistre-le. Le champ reste vide ensuite ; **jeton enregistré** signifie qu’il est sauvegardé, et les statistiques confirment que Lichess l’accepte. Un jeton refusé ou expiré donne un message de reconnexion. Tu peux supprimer le jeton dans ces mêmes réglages.

Le jeton est conservé côté serveur dans la base locale, jamais dans le stockage du navigateur ni dans les réponses de lecture. Les sauvegardes personnelle et complète contiennent aussi ce jeton. Pour un serveur administré, la variable **CHESSGYM_LICHESS_TOKEN** prend priorité sur le réglage local ; elle se modifie sur le serveur.

Seuls la position et les filtres sont envoyés à Lichess, avec le jeton d’authentification. Tes PGN et leurs informations personnelles ne sont pas transmis. Un cache temporaire limite les requêtes ; les erreurs et limites de débit sont signalées, avec une indication si d’anciennes statistiques sont affichées. Les bases locales restent utilisables sans connexion Lichess, en désactivant la référence distante si désiré.

Références : [API de l’explorateur](https://lichess.org/api#tag/Opening-Explorer), [changements annoncés par Lichess](https://lichess.org/changelog).

## Répertoires

Dans les réglages d’une base, active **Répertoire d’ouvertures**, choisis le camp et, au besoin, **Principal**. Tu peux conserver plusieurs répertoires blancs et noirs ; un seul de chaque camp est principal. La page **Répertoires** permet aussi de choisir les principaux.

Le panneau **Répertoires principaux** vérifie automatiquement la suite jusqu’à la position affichée, pour les Blancs et les Noirs. Il fonctionne depuis une partie sauvegardée, une analyse libre ou un PGN collé, ainsi que dans la fenêtre d’analyse Stockfish détachée. Il n’est donc plus nécessaire de sauvegarder une partie avant de prolonger un répertoire. **↻ Vérifier** force une nouvelle vérification au besoin.

Si la suite appartient au répertoire puis dépasse la fin d’une branche **sans déviation**, **Ajouter jusqu’ici** copie uniquement les coups supplémentaires jusqu’à la position affichée. Les commentaires et annotations de ces nouveaux coups sont conservés, ainsi que les autres branches du répertoire. Exemple : avance de deux coups intéressants dans une partie de maître compatible, puis ajoute-les en un clic. La partie source reste intacte. Si elle ou le répertoire a changé pendant l’opération, ChessGym demande une nouvelle vérification plutôt que d’écraser une modification.

Dans **Analyse → Répertoire → Transpositions de cette position**, recherche les lignes de tous tes répertoires ou d’une base choisie qui aboutissent à la position affichée. Compare les ordres de coups, les commentaires et les suites, puis utilise **Ouvrir cette ligne à la même position**. Ton analyse et ses annotations en cours sont conservées. Tu peux inclure le même ordre de coups pour retrouver les autres occurrences; une recherche limitée est signalée comme partielle. Une ligne modifiée depuis la recherche demande une actualisation.

Une position déjà connue par **transposition** peut être signalée, mais cela ne rend pas automatiquement compatible un parcours qui a dévié du répertoire : l’ajout reste fondé sur la suite exacte. Une position FEN isolée ne suffit pas à reconstituer les coups depuis le début ; ouvre son PGN complet pour vérifier cette compatibilité. Aucune aide de répertoire n’apparaît automatiquement sur l’échiquier d’une révision en cours.

### Trouver les réponses à préparer

Ouvre **Répertoires → À compléter**, ou l’onglet **À compléter** d’une base marquée comme répertoire. Dans les réglages de cette vue, choisis les tranches de classement **Lichess** et les cadences. Ce ne sont pas des équivalences Chess.com. Le seuil initial est **1 % (une partie sur 100)**, jusqu’à **20 demi-coups (10 coups complets)**.

**Explorer le répertoire** recherche les premières réponses adverses non préparées et les positions où ton coup reste à choisir. Les lignes sont classées par probabilité décroissante. **Explorer cette position** ouvre la suite complète dans l’analyse, avec le même camp et les mêmes filtres. Joue et annote ta réponse, puis **Sauvegarder** ajoute cette nouvelle ligne dans la base proposée; les autres lignes sont conservées.

Depuis **Analyse → Répertoire**, **Plus grande lacune** ouvre directement la position non couverte la plus probable du bilan de ton répertoire principal blanc ou noir. Le bilan est vérifié au clic et actualisé si nécessaire, avec les classements et cadences mémorisés pour ce répertoire. L’analyse reçoit toute la ligne et propose la bonne base pour sa sauvegarde. Les annotations en cours d’une partie sauvegardée sont conservées; remplacer une analyse libre non sauvegardée demande confirmation. Une exploration partielle est signalée : le bouton choisit alors la lacune la plus probable déjà trouvée. **Continuer l’exploration** ou **À compléter** permettent de poursuivre ou d’affiner le bilan.

Seules les réponses adverses diminuent la probabilité : les coups de ton camp sont supposés joués. Lorsqu’une position possède plusieurs parcours, le classement retient le chemin le plus fréquent, sans additionner les alternatives ou les transpositions. Les statistiques depuis un diagramme sont conditionnelles à ce départ. Cette vue n’annonce pas un pourcentage global de couverture. Une fin de ligne sans réponse est une piste à prolonger jusqu’à l’horizon choisi, pas nécessairement une erreur de ton répertoire.

L’examen procède par passes limitées; **Continuer l’exploration** réutilise les positions déjà calculées. Les statistiques manquantes ou un refus temporaire de Lichess sont signalés comme incomplets. Le cache sur disque est partagé avec l’explorateur, accepte jusqu’à sept jours pour ces examens et survit aux redémarrages. Les requêtes sont espacées et une seule est envoyée à la fois; un refus 429 entraîne une pause d’au moins 60 secondes, avec respect de `Retry-After`. Une modification du répertoire rend son ancien bilan caduc. **Recalculer** refait le parcours avec les statistiques encore valides du cache.

Dans **Réglages de la base → Révisions → Priorité des coups d’ouverture**, **Fréquence de rencontre** utilise le dernier examen pour classer les nouveaux coups et les révisions dues. Les reprises après erreur et les journées de retard plus anciennes gardent la priorité; aucune échéance n’est avancée. Les cartes **Maîtrisé** et l’historique sont conservés. Sans estimation valide, l’ordre habituel est utilisé. **Ordre des échéances** permet de revenir au tri précédent. Aucune requête Lichess n’est déclenchée par l’ouverture d’une carte.

## Révisions

Dans **Bases à réviser**, choisis **Réviser** ou **Apprendre** pour une base, ou **Tout réviser** et **Tout apprendre** pour toutes les bases activées. Le premier choix propose les cartes déjà travaillées qui sont dues, entretien des acquis compris; le second propose uniquement les cartes jamais travaillées. Les filtres de la liste ne limitent pas les actions globales. Les réglages de chaque base et les reprises restent conservés. L’onglet Séance du jour et sa préparation sont retirés; les objectifs se règlent dans le plan d’entraînement.

Chaque carte garde sa base, ses réponses, son mode de validation et ses délais. La sélection alterne les bases et les catégories pour éviter qu’une grosse base occupe toute la séance. **Pause** conserve l’ordre et les réponses enregistrées; le temps passé en pause ou dans un onglet caché n’est pas ajouté au temps actif. À la reprise, les cartes supprimées, désactivées ou déjà travaillées ailleurs sont revérifiées.

Dans **Réglages → Révisions → Entretien des acquis**, tu peux activer les rappels, choisir leur intervalle et leur maximum quotidien. Par défaut : **activé**, **30 jours** après la maîtrise et au plus **5 rappels par journée d’étude**. Les cartes déjà maîtrisées lors de la mise à jour sont réparties progressivement à partir de la prochaine journée d’étude. Une réussite conserve la maîtrise et prévoit un nouveau rappel; un échec remet la carte en apprentissage. Désactiver l’entretien conserve les acquis, leurs rappels et leur historique. Modifier les réglages ne réécrit pas les échéances d’entretien déjà enregistrées.

Les réglages de résolution et d’espacement appartiennent à chaque base : **Révisions** regroupe les bases activées avec leurs totaux. Une barre de progression par base répartit les cartes entre **Maîtrisées**, **Apprises**, **À réviser** et **Non apprises**. Chaque carte occupe un seul segment : une carte déjà vue dont l’échéance est atteinte passe dans **À réviser**; une carte maîtrisée reste dans **Maîtrisées**. Les nouvelles cartes et les tentatives manquées encore en attente de leur prochaine reprise restent **Non apprises**. Difficile, Bien et Facile valident la carte comme **Apprise**. La somme des segments égale le total. Les compteurs historiques restent disponibles; leur nombre d’appris inclut les cartes maîtrisées et peut aussi inclure des cartes dues.

L’onglet **Statistiques** permet de choisir toutes les bases ou une seule, ainsi que les 7, 30, 90 ou 365 derniers jours d’historique. Les filtres sont conservés lorsque tu changes d’onglet ou reviens dans Révisions pendant cette utilisation de l’application.

- **Aujourd’hui** : réponses enregistrées, cartes distinctes, durée, part des notes Bien/Facile et révisions dues maintenant. Une réponse correspond à la validation d’une carte; revoir la même carte plusieurs fois compte plusieurs réponses.
- **Planifier ma séance** : charge cumulée maintenant, dans 1 heure, 4 heures, 1 jour, 3 jours et 7 jours. Le temps estimé utilise la durée médiane des réponses des 90 derniers jours, séparément pour ouvertures, positions à résoudre et positions à jouer. Sans durée mesurée, les valeurs indicatives sont 15, 45 et 120 secondes par carte; elles sont indiquées dans le détail du calcul.
- **Échéances à venir** : cartes déjà programmées pour les 30 prochains jours, avec le retard antérieur affiché séparément. Ces dates ne prédisent ni les nouvelles cartes ni les répétitions déclenchées par tes prochaines réponses.
- **Calendrier et activité** : jours étudiés, séries de jours actifs dans la période choisie, nombres de réponses ou temps enregistré par jour. Les dates suivent le fuseau horaire de ton navigateur, y compris les changements d’heure.
- **État des cartes, notes et intervalles** : la même répartition en quatre segments exclusifs, la distribution Manqué/Difficile/Bien/Facile et l’espacement actuel des cartes encore soumises aux répétitions. La répartition des notes reflète tes validations, pas une mesure indépendante de mémorisation.
- **Par base** : charge et activité, avec accès à la base et lancement d’une séance. Les nouvelles cartes disponibles respectent les limites quotidiennes existantes, renouvelées selon le fuseau et le début de journée d’étude choisis dans les réglages.

Les échéances et les cartes actives concernent uniquement les bases dont les révisions sont activées. L’activité passée conserve les réponses des cartes retirées des révisions et des bases désactivées encore présentes. Supprimer une base supprime aussi son historique. Une ouverture compte une carte par décision de ton camp; un exercice à résoudre ou à jouer compte une carte pour son point de départ.

La séance reprend la présentation de l’analyse : grand échiquier, Stockfish en haut du carnet, puis liste des coups joués, bilan et boutons de difficulté. Le moteur reste désactivé au départ; son utilisation marque la tentative comme assistée. Les réponses et explications restent masquées jusqu’à la fin de la tentative ou à leur révélation.

**Analyser / éditer** ouvre la partie ou l’exercice source complet dans l’analyse, à la position de départ de la carte, avec tous ses coups, variantes et commentaires. Tu peux alors modifier le contenu et cliquer sur **Sauvegarder** pour le conserver dans sa base. Ouvrir l’éditeur ne donne aucune note à la tentative. Les coups improvisés contre le moteur pendant une révision ne remplacent pas le PGN source.

Après l’édition, **Retour à la révision**, en haut de l’analyse, reprend la séance au même exercice. Les cartes déjà terminées, l’ordre de la séance, les coups déjà joués et les erreurs restent conservés. Les modifications non enregistrées restent dans le brouillon d’analyse; le retour ne les sauvegarde pas dans la base. Les réponses et explications sont actualisées depuis la version enregistrée; si tes changements sauvegardés rendent les coups déjà joués incompatibles, seul l’exercice courant recommence, avec une indication. Une carte retirée de la base est sautée sans lui attribuer de note. Le temps passé à éditer ne compte pas dans la durée de la tentative. Consulter la solution complète marque une tentative encore en cours comme assistée.

À la fin d’un exercice résolu ou révélé, le commentaire PGN du coup final apparaît une seule fois : dans la notation lorsqu’elle est visible, ou dans l’onglet **Exercice** sur téléphone. Une explication de départ différente reste disponible. La ligne réellement jouée détermine le commentaire, y compris pour une variante du PGN. **Position finale** et la reprise conservent ces annotations. Si leur chargement échoue, un bouton permet de réessayer sans bloquer la note ni perdre le résultat; le PGN source reste inchangé.

Une fois la solution trouvée ou affichée, tu peux déplacer librement les pièces, revenir sur les coups et explorer les lignes Stockfish directement dans la révision. **Position finale** ramène au dernier coup de l’exercice sans effacer les variantes explorées. Ces variantes restent temporaires : la solution enregistrée et la note proposée sont conservées, et le temps d’exploration ne s’ajoute pas à la durée de résolution. **Recommencer** revient à une tentative guidée; tes erreurs déjà comptées restent conservées.

Le bouton **Révisions** de la navigation reprend directement la séance en cours après un passage dans l’analyse, la bibliothèque ou les réglages. Dans le menu **Échiquier**, la ligne **Échiquier actuel** retrouve ton analyse précédente. Les pauses entre les écrans ne comptent pas comme une aide ni dans le temps de résolution. Le bouton de retour dans la séance permet de la quitter explicitement et de retrouver la liste des bases à réviser.

| Type | Fonctionnement |
| --- | --- |
| Mémoriser des coups | Une carte par décision de ton camp, avec les réponses prévues dans le PGN. Chaque coup possède son propre historique. |
| Résoudre une position | Joue la solution jusqu’au bout. Le PGN doit contenir les coups attendus après le point de départ. |
| Jouer contre le moteur | Entraîne une position avec Stockfish, le camp, la force et l’objectif choisis dans la base. Un diagramme seul suffit. |

**Manuelle** te laisse choisir Manqué, Difficile, Bien ou Facile. **Automatique** propose le résultat selon les erreurs et les aides, après exécution de la réponse attendue. **Hybride** propose ce résultat et te laisse l’ajuster. Une erreur reste comptée même si tu corriges le coup ensuite.

L’espacement est **adaptatif** : après un intervalle d’au moins un jour, Difficile le multiplie initialement par **1,2**, Bien par **2** et Facile par **3**, sans descendre sous les délais minimaux configurés. Ces trois multiplicateurs sont modifiables globalement dans **Réglages → Révisions**, de 0,1 à 10, et s’appliquent aux prochaines réponses de toutes les bases. Les échéances déjà enregistrées restent inchangées. Les délais proposés initialement dans **Réglages → Révisions** sont **Manqué : 10 minutes**, **Difficile : 2 jours**, **Bien : 5 jours** et **Facile : 10 jours**. Ces valeurs globales servent de point de départ aux nouvelles bases; chaque base conserve ensuite ses propres valeurs. Le plafond par défaut reste de **720 jours**; les anciennes bases au plafond de 180 jours ont été migrées vers 720 jours et les anciennes configurations à intervalles fixes vers l’adaptatif. Dès que le nouvel intervalle calculé dépasse le **seuil global de maîtrise**, initialement **180 jours**, la carte devient automatiquement **Maîtrisée** et quitte le calendrier ordinaire. Son prochain rappel d’entretien est conservé séparément. Le seuil est configurable dans **Réglages → Révisions**, de 1 à 3 650 jours. Un intervalle exactement égal au seuil reste révisable.

**Maîtrisé** conserve la carte dans les **appris** et la retire des révisions ordinaires, y compris **Libre**, sauf lorsqu’un rappel d’entretien est dû. Cette action est disponible pendant une carte, même avant de la résoudre, dans les trois modes de validation. Elle concerne uniquement la carte affichée : un coup individuel pour une ouverture, ou l’exercice pour une position à résoudre/jouer. Le sous-total des cartes maîtrisées apparaît dans Révisions et Statistiques. Une déclaration manuelle de maîtrise conserve l’historique existant et n’ajoute pas de note ni de réponse au calendrier d’activité. La maîtrise automatique consécutive à une réponse conserve cette réponse dans l’historique. Les cartes ayant déjà un intervalle supérieur au seuil deviennent aussi maîtrisées, à la mise à jour ou lors d’un changement du seuil, sans ajouter de réponse fictive ni effacer leur historique. Relever le seuil ne réactive pas les cartes déjà maîtrisées.

Chaque base propose **Réviser** pour les cartes déjà travaillées qui sont dues, rappels d’entretien compris, et **Apprendre** pour les cartes jamais travaillées. Une carte déjà tentée mais ratée revient dans Réviser à son échéance. Les cartes dont la révision est dans le futur ne sont pas proposées. Les anciennes limites quotidiennes de nouvelles cartes sont ignorées; les objectifs de séance et des blocs du programme contrôlent la quantité de travail. Les blocs du plan d’entraînement peuvent choisir Réviser, Apprendre ou les deux; toutes les révisions sélectionnées passent avant les nouvelles cartes. Les réponses mettent à jour l’historique et les échéances, et le choix est conservé lors des pauses et reprises.

Pour les positions jouées, la force Stockfish va de 0 à 20, sans équivalence Elo annoncée. L’analyse reste à pleine force. À la fin d’une partie, son résultat sert au bilan. Si tu termines avant un résultat définitif, tu indiques toi-même si l’objectif a été atteint.

## Apparence

La langue de l’interface se choisit dans **Réglages → Général → Langue** parmi les 12 langues disponibles. Le choix est conservé dans ChessGym et sur l’appareil. Les noms de bases, joueurs, commentaires, variantes et contenus PGN ne sont pas traduits.

Dans **Réglages → Apparence**, combine librement **8 thèmes d’interface**, **8 jeux de pièces** et **12 couleurs d’échiquier**. Les thèmes comprennent Graphite & cuivre, Ardoise & sauge, Bleu de minuit, Prune, Forêt, les thèmes clairs Perle et Lin, et Contraste élevé. Les pièces Cburnett (défaut), Merida, Chessnut, Celtic, Fantasy, Shapes, Pirouetti et Spatial sont accompagnées d’aperçus. Les échiquiers proposent Brun classique, Bleu, Vert, Ardoise, Noyer, Sable, Olive, Océan, Lavande, Rosé, Glacier et Graphite.

Chaque choix est enregistré automatiquement dans ChessGym et retrouvé à la prochaine ouverture. Les pièces et couleurs s’appliquent aux analyses, révisions et positions jouées; le thème de l’interface reste indépendant. Tous les jeux de pièces sont fournis localement, sans téléchargement pendant l’utilisation. Leurs attributions et licences figurent dans [les notices des pièces](PIECE-SETS-NOTICES.md).

## Grandes bases de référence

Dans **Bibliothèque → Importer une grande base…**, choisis un nom et un dossier, puis indique le chemin complet d’un fichier **PGN** ou **PGN.ZST** présent sur le PC ou le serveur qui héberge Chess Gym. Depuis un téléphone, ce chemin désigne donc un fichier du serveur. Le fichier est lu progressivement; il ne passe pas par le formulaire d’import PGN ordinaire.

Dans **Options avancées → Encodage du fichier**, conserve **UTF-8** pour Lichess. Pour un ancien export ChessBase, sélectionne **Windows-1252** ou **Latin-1** si c’est l’encodage choisi à l’exportation. Chess Gym ne remplace pas automatiquement les caractères illisibles : les erreurs de lecture sont signalées dans le bilan d’import.

Le maximum proposé est **100 000 parties lues** pour un premier essai. Laisse ce champ vide pour lire tout le fichier. **Mettre en pause** conserve le travail déjà effectué; **Poursuivre l’importation** reprend la lecture avec la même limite par passage. Les parties écartées et les doublons restent comptabilisés séparément. Un seul import de grande base s’exécute à la fois. Sa lecture et sa validation utilisent automatiquement jusqu’à **4 cœurs**, selon le processeur, avec un indicateur pendant l’import. Les parties sont enregistrées dans l’ordre du fichier et la reprise conserve toute la progression sauvegardée. Aucune analyse Stockfish complète n’est lancée par cet import.

La progression de lecture du fichier et la fin du traitement sont distinctes. **100 % de lecture ne signifie pas encore que l’import est terminé** : l’écriture finale sur disque peut continuer. Les compteurs affichent uniquement le dernier lot enregistré, jamais des parties encore en attente de validation.

Les nouveaux imports indiquent leur étape : **Préparation**, **Reprise du fichier compressé**, **Lecture et indexation**, **Enregistrement du lot**, puis **Finalisation sur disque**. Pour reprendre un PGN.ZST, le début déjà traité est décompressé à nouveau avant de continuer, sans réinsérer ses parties. Après **Mettre en pause**, **Pause demandée** reste affiché jusqu’à l’arrêt effectif du processus ; une longue finalisation ne doit pas être interrompue en fermant de force l’application. Un import lancé avant cette mise à jour conserve un statut général, sans inventer son étape détaillée. Les étapes sont des indications de suivi : les véritables points de reprise restent enregistrés dans la base SQLite.

Sur le serveur, la variable facultative `CHESSGYM_IMPORT_WORKERS` permet de choisir de **1 à 16** processus de lecture, avant de démarrer Chess Gym. La valeur `auto` conserve le réglage automatique. Augmenter ce nombre n’accélère pas nécessairement les écritures sur disque; le réglage par défaut laisse de la capacité pour l’application et Stockfish.

Le lanceur Windows **Démarrer ChessGym** utilise automatiquement **de 1 à 4 processus d’importation**, selon le nombre de processeurs disponibles. `Start-ChessGym.ps1 -ImportWorkers 4` permet de choisir une valeur explicite; `-ImportWorkers 0` rétablit le choix automatique. Un serveur déjà lancé conserve son réglage jusqu’au prochain redémarrage; les imports reprennent alors à leur dernier point sauvegardé.

Le lanceur réserve aussi jusqu’à **256 Mio de cache SQLite pour l’import**, afin de réduire les relectures d’index dans les grandes bases. Ce budget concerne le seul processus qui écrit dans la base; il n’est pas multiplié par le nombre de processus de lecture. Les consultations gardent leur cache de **16 Mio par connexion**. `Start-ChessGym.ps1 -ImportCacheMB 512` permet de choisir un budget de **64 à 4 096 Mio** au prochain démarrage. Pour un lancement manuel du serveur, la variable `CHESSGYM_IMPORT_CACHE_MB` accepte les mêmes valeurs; sans configuration, le budget reste à **128 Mio**. Ce réglage ne change ni les parties, ni la taille des lots sauvegardés, ni la reprise d’un import. Son gain dépend de la taille de l’index et du disque.

Pour les essais de performance, `CHESSGYM_IMPORT_SORT_POSITIONS=1` active l’écriture des positions triées à l’intérieur de chaque lot; `0` conserve l’écriture partie par partie. Ce mode reste désactivé par défaut tant que les mesures ne justifient pas son activation. Il conserve l’ordre des parties, toutes les positions de la ligne principale et les mêmes points de reprise. Le tampon est borné; les parties, leurs positions et leur progression sont sauvegardées dans une même transaction. Le mode peut changer lors d’une reprise sans recommencer l’import. Le gain dépend de la taille de l’index, du cache et du disque.

La base apparaît dans les dossiers habituels. Sa liste affiche **50 parties par page**, avec recherche simple ou avancée, tri par ordre du fichier, date, joueurs ou classement, et accès aux annuaires **Joueurs** et **Tournois**. Les filtres Elo portent par défaut sur **les deux joueurs**; le champ correspondant permet de changer cette portée. Si la date habituelle est inconnue mais que le PGN fournit une date UTC, celle-ci est utilisée. Les statistiques calculées pendant un import ou après une limite de lecture concernent uniquement les parties déjà disponibles.

Les recherches par joueur ou événement utilisent les index de noms, sans lire les PGN. Sur une grande base terminée, une recherche longue continue en arrière-plan et ses résultats exacts apparaissent automatiquement; **Actualiser** permet de reprendre le suivi après cinq minutes. Chaque page calculée est conservée pour cette version de la base et ces filtres, y compris après un redémarrage. Les recherches textuelles incluent toujours les fragments de noms, pas seulement leur début.

**Analyser** ouvre la partie complète, avec ses commentaires, variantes et annotations. **Sauvegarder** en crée une copie dans une base personnelle, où tu peux l’annoter, la modifier ou la réviser. Les réglages de la base portent sur le nom, le dossier, les catégories et le logo. Le PGN source reste conservé à son emplacement.

**Gérer les parties de référence** : coche les parties voulues, puis utilise **Dupliquer…**, **Déplacer…** ou **Supprimer…**. Le menu **⋯** propose aussi ces actions pour une seule partie. La case d’en-tête sélectionne seulement la page affichée; la sélection est conservée entre les pages et les filtres, avec un compteur des parties masquées. Tu peux dupliquer dans la base actuelle, une autre base de référence ou une base personnelle. Un déplacement copie les parties vers la destination puis les retire de la référence d’origine. La suppression demande confirmation et retire aussi les parties des index de recherche. Les coups, variantes et commentaires sont conservés dans les copies. Mets l’import en pause avant de modifier les parties; le fichier PGN original reste intact. Pour modifier les informations PGN, annoter ou réviser, travaille sur une copie dans une base personnelle.

L’explorer local et l’onglet **Position** utilisent un index des **lignes principales entières**, y compris les positions de fin de partie. Les variantes sont conservées dans les PGN consultables, mais ne sont pas incluses dans cet index de référence pour cette première version. La recherche de position tient compte du trait, du roque et de la prise en passant légale, sans exiger les mêmes compteurs de coups.

L’**explorer** limite les calculs coûteux sur les grandes bases à une recherche à la fois. Pour une base importée entièrement, un calcul dépassant **6 secondes** continue en préparation en arrière-plan : l’interface affiche son avancement et vérifie automatiquement le résultat pendant cinq minutes, puis propose **Actualiser**. La première préparation crée aussi un index compact, sans modifier les PGN; cette étape unique peut prendre plusieurs minutes sur une très grande base. Les statistiques exactes sont conservées sur disque pour la position, les bases et les filtres concernés, y compris après un redémarrage. Les parties rejetées pendant l’import restent signalées et exclues des calculs. Pendant un import encore actif, les recherches restent limitées à six secondes et les résultats partiels sont conservés jusqu’à **30 secondes**. Une interruption ne signifie jamais qu’il n’y a aucune partie.

Les fichiers ChessBase **CBV / CBH / 2CBH** doivent d’abord être exportés en PGN dans ChessBase. Pour un fichier PGN.ZST, aucune décompression complète sur disque n’est nécessaire. Les grandes bases disposent de leur propre stockage indexé dans **data/references**, séparé de la progression des révisions et des bases personnelles.

## Sauvegarder et déplacer

**Réglages → Sauvegardes** permet de programmer des copies personnelles : dossier sur le serveur, fréquence en heures et nombre de copies automatiques conservées. Une installation neuve laisse la programmation désactivée; les valeurs proposées sont 24 heures et 7 copies. **Créer une copie maintenant** conserve une copie manuelle dans ce dossier. **Vérifier** contrôle son intégrité. La rotation ne retire que les anciens fichiers automatiques de ChessGym après vérification réussie d’une nouvelle copie, jamais les copies manuelles ni les autres fichiers du dossier.

Dans **Réglages**, la **sauvegarde personnelle** est le choix courant. Son archive ZIP contient les PGN des bases personnelles et le fichier SQLite avec le profil local, les réglages, les annotations enregistrées, les progrès de lecture et de révision, les brouillons, les séances conservées, l’historique des parties contre l’ordinateur et leurs pendules, les comptes de synchronisation et les bilans d’analyse. Elle **ne copie pas les grandes bases de référence ni leurs index**. Leur liste reste dans la bibliothèque, et le manifeste `metadata.json` précise quels fichiers de référence ont été omis.

La **sauvegarde complète** reste disponible séparément : elle ajoute les fichiers du dossier **data/references**. Elle peut prendre beaucoup de temps et demander un espace temporaire important avec Mega ou une archive Lichess. Aucun des deux modes ne recopie les fichiers PGN ou PGN.ZST sources situés ailleurs. Garde ces archives privées : elles contiennent notamment les données personnelles et les jetons enregistrés. Sur un serveur encore ancien, seul le fonctionnement de sauvegarde complète existant est annoncé ; la sauvegarde personnelle exige le serveur mis à jour.

Pour restaurer les données personnelles avec une version compatible de ChessGym :

1. Vérifie la copie souhaitée, puis arrête ChessGym.
2. Sous Windows, ouvre **Restaurer ChessGym.cmd**, choisis ton archive et confirme. Sous Linux, vérifie avec `.venv/bin/python scripts/restore_backup.py /chemin/sauvegarde.zip`, puis relance cette commande avec `--confirm` après l’arrêt du serveur.
3. Le programme vérifie la base, conserve une copie de sécurité de l’état actuel et restaure les données personnelles. Il refuse de remplacer les données pendant que le nouveau serveur fonctionne. La partie SQLite personnelle de l’archive est limitée à 1 Gio. Les anciennes sessions de connexion sont invalidées; les anciens brouillons locaux restent séparés des données restaurées.
4. Les grandes références existantes restent en place. Sur une autre machine, transfère séparément le dossier `references` d’une sauvegarde complète, ou les fichiers portant les noms indiqués dans `metadata.json`. Ne remplace pas leurs fichiers pendant un import. Sans eux, les références sont indisponibles, mais la progression et les parties personnelles sont restaurées.
5. Relance ChessGym et reconnecte-toi. Pour poursuivre un import incomplet, son fichier source doit rester accessible au chemin configuré.

Le serveur et le stockage sont indépendants du navigateur : une migration vers ton serveur réutilisera ces bases. Les parties de référence déjà importées restent consultables sans leur fichier source; poursuivre un import incomplet demande que le chemin source soit encore accessible. Le lancement fourni écoute seulement sur ce PC. L’accès depuis une tablette demandera de configurer l’adresse réseau du serveur. L’interface s’adapte déjà aux petits écrans.

## Nouveaux entraînements

Les barres de navigation sont centrées. **Jouer contre l’ordinateur**, **Deviner le coup**, **À l’aveugle**, **Coordonnées** et **Color** proposent **Jouer**, **Historique**, **Statistiques** et **Réglages**. Les statistiques portent sur tout l’historique enregistré dans ChessGym pour le mode choisi; les résultats excluent les séances encore en cours ou interrompues. Les durées non mesurées restent inconnues. Les réglages préparent les prochaines séances et ne remplacent pas une séance active. Les choix de Deviner le coup, À l’aveugle, Coordonnées et Color sont conservés dans l’espace local après validation.


La barre principale regroupe **Bibliothèque** (bases, mes parties, répertoires), **Entraînement** (révisions, lecture, puzzles, deviner le coup, à l’aveugle, coordonnées) et **Échiquier**.

- **Partie complète** : dans les réglages de révision d’une base, choisis ce type pour apprendre tous les coups de la ligne principale, avec les blancs et les noirs. Une seule note finale programme la prochaine révision de la partie. Les ouvertures restent évaluées coup par coup; leur bouton **Ligne / PGN complet** permet une consultation temporaire, puis le retour exact à la carte.
- **Deviner le coup** : choisis une partie et le camp à deviner, ou lance le mode depuis le menu de l’analyse. Le pointage repose uniquement sur l’évaluation de Stockfish : chaque coup, y compris celui de la partie, est noté selon son écart avec le meilleur coup. La suite reprend les coups originaux. Les noms et Elo disponibles encadrent l’échiquier; le tournoi et la date figurent en haut. Les pendules disponibles suivent la position originale révélée, sans décompter pendant ta réflexion, et sont masquées pendant l’exploration d’une variante. Les informations absentes restent masquées. Les tentatives n’altèrent pas le PGN source.
- **Puzzles** : mode classique/calcul avec cote personnelle, statistiques et historique des coups entrés. Choisis la sélection **Standard**, une sélection **Personnalisée** ou l’une de tes sélections enregistrées. Le temps ne modifie pas la cote. Les réglages permettent de copier automatiquement les échecs dans une base, dès la première erreur ou aide, y compris pendant le puzzle classique en cours. Les copies existantes et leurs annotations sont conservées. À la fin, la position reste affichée pour l’explorer : une coche verte indique la réussite; un résultat avec erreur ou aide reste « À retravailler ».
- **Puzzle Storm** : parcours de trois minutes avec difficulté croissante et bonus de séries. Chaque bon coup du joueur fait avancer le combo : **+3 s à 5 coups, +5 s à 12, +7 s à 20, puis +10 s à 30 et tous les 10 coups suivants**. Une erreur retire 10 s et remet le combo à zéro. La barre affiche le prochain bonus, et le gain ou la perte de temps apparaît près du chrono. Le Standard suit les tranches de cote et leurs nombres de puzzles dans le [sélecteur Lichess](https://github.com/lichess-org/lila/blob/master/modules/storm/src/main/StormSelector.scala), sur 137 puzzles; une réussite comme une erreur fait avancer dans la série. La sélection locale utilise des cibles ordonnées dans ces tranches, exclut les puzzles « equality » et demande une incertitude de cote (RD) ≤85. Les chemins de sélection et leur classement qualitatif sur Lichess ne sont pas disponibles dans la banque locale : le choix précis des puzzles reste donc une approximation. Le chrono reste à **3:00** jusqu’au premier coup joué, correct ou non, puis continue pendant toute la séance. Observer la position ou sélectionner une pièce ne le lance pas. Le temps d’attente avant ce premier coup est exclu du temps du puzzle. Les sélections personnalisées s’appliquent aussi à Storm : la difficulté progresse dans la plage et les filtres choisis, avec un seul camp pendant la séance. Les records sont séparés entre Standard et chaque configuration personnalisée; renommer une sélection ne remet pas son record à zéro. Storm ne modifie pas la cote classique. Dans les réglages des puzzles, une option distincte permet de copier les mauvaises réponses Storm dans une base de ton choix; elle est désactivée par défaut. L’expiration du chrono seule ne déclenche pas de copie.
- **Enchaînement Storm** : le prochain puzzle est préparé à l’avance côté serveur. Il arrive avec la réponse au dernier coup, déjà prêt à jouer, sans pause imposée entre les puzzles. Un rappel discret indique le résultat du puzzle précédent. Si une sélection doit être recalculée, le temps effectivement consacré à sa préparation côté serveur est rendu au chrono; attendre volontairement avant de cliquer sur « Puzzle suivant » continue de consommer du temps.
- **Bilan Storm** : à la fin de la séance, retrouve tous ses puzzles dans l’ordre, avec leur résultat, cote et temps. Filtre les réussis, manqués ou non terminés, puis utilise **Revoir** ou **Créer un exercice** sur chaque ligne. Un puzzle interrompu par le chrono reste distinct des erreurs. Le bouton **← Bilan** revient à la même liste et conserve son filtre. Les bilans passés restent accessibles depuis **Statistiques → Historique Storm**.
- **Créer un exercice depuis un puzzle** : après résolution, depuis l’historique ou directement depuis le bilan Storm, ouvre l’éditeur avec la position de départ et la solution exacte du puzzle déjà saisie. Les essais erronés et variantes explorées ne sont pas inclus. Tu peux modifier la solution, ajouter des commentaires ou variantes, puis choisir une base existante ou en créer une. L’exercice n’est enregistré qu’en cliquant sur **Créer l’exercice**; le puzzle ou le bilan en arrière-plan reste intact.
- **À l’aveugle** : puzzles d’ouverture avec liste des coups, finales avec description des pièces, ou reconstitution d’une position après X coups ou toute une partie d’une base. Choisis de conserver ou masquer la présentation; réponds sur un échiquier vide ou en notation. Par défaut, les puzzles d’ouverture et de finale demandent ensuite de **reconstituer la position finale**. Place les pièces de mémoire sur l’échiquier vide, puis valide : la position attendue reste cachée jusque-là. Le résultat distingue la résolution des coups et la reconstitution, avec leur temps respectif. Seule la résolution complète sans erreur détermine la réussite et la cote; la reconstitution finale est facultative et ne modifie pas cette cote. La case **Reconstituer aussi la position finale** permet de désactiver cette seconde étape. **Révéler et terminer** dévoile la solution en conservant ce recours dans le bilan. Une partie source d’ouverture absente du cache nécessite un accès à Lichess; le jeton configuré dans l’explorateur est réutilisé côté serveur lorsque Lichess demande une connexion.
- **Coordonnées** : cases, destinations de coups et mode mixte; séances de 30 ou 60 secondes, orientation blanche ou noire, records séparés selon les options.
- **Color** : le nom d’une case apparaît; indique si elle est **Blanche** ou **Noire** avec les boutons ou les flèches gauche/droite du clavier. Choisis **30 ou 60 secondes**. Le chrono démarre à la première réponse; chaque réponse mène à une nouvelle case, même après une erreur. Les records sont séparés par durée : seule une séance menée jusqu’à la fin, avec au moins une réponse et **aucune erreur**, est admissible. Un pourcentage arrondi à 100 % ne suffit pas. Recommencer avant l’échéance classe la séance précédente comme interrompue, hors records. Les dernières séances restent consultables pour suivre tes résultats.
- **Réglages → Sons** : activation, volume, déplacements, bonnes/mauvaises réponses et sons de navigation facultatifs. Les impacts de bois et signaux courts Kenney sous CC0 sont inclus localement, sans connexion externe pendant le jeu; voir [leur provenance](static/sounds/kenney/README.md). Les aperçus au survol restent silencieux.

La banque publique de puzzles Lichess s’importe depuis un CSV, CSV.ZST ou CSV.GZ sur le serveur, dans **Puzzles**. Les scripts `download_puzzle_bank.py` et `import_puzzle_bank.py`, dans `scripts/`, permettent aussi de la télécharger et de l’importer. Elle se trouve dans **data/puzzles/bank.sqlite3**, séparément de tes parties. Les historiques et cotes personnels sont inclus dans les sauvegardes personnelles; la banque publique est exclue de celles-ci et incluse dans les sauvegardes complètes. Lors d’une restauration complète sur une autre machine, transfère aussi `puzzles/bank.sqlite3` hors ligne, comme les grandes références. Aucun son externe ni base commerciale n’est fourni avec ces modes.

## Installation sur une autre machine

Un environnement Python ne se déplace pas tel quel : recrée-le sur une autre machine. L’archive source ne contient ni environnement Python, ni moteur, ni données personnelles.

Les étapes Windows sont dans [README.md](README.md#install-on-windows); les instructions Linux non encore validées de bout en bout sont dans le [guide détaillé](USAGE.md#install-on-linux). Pour une nouvelle installation : Python 3.12, environnement virtuel, puis installation de `requirements.txt` (ou `requirements-dev.txt` pour les tests). Lance `run.py`. Les variables CHESSGYM_DATA_DIR, CHESSGYM_HOST, CHESSGYM_PORT et CHESSGYM_ENGINE permettent de choisir les données, l’adresse locale, le port et le moteur UCI. CHESSGYM_HOST accepte seulement localhost ou une adresse de boucle locale, par exemple 127.0.0.1 ou ::1. Sous Linux, installe un Stockfish adapté et indique son chemin ; un exécutable Windows ne convient pas. Le script facultatif `scripts/prepare_local.py` ne réécrit aucun fichier de dépendances et ne télécharge un moteur Windows que sur Windows x86-64.

L’application s’ouvre sans connexion et accepte uniquement les accès depuis cet ordinateur. Les adresses d’écoute réseau sont refusées; cette version ne propose pas d’accès distant. Le lanceur Windows utilise le port 8765 ; les journaux sont dans data/server.out.log et data/server.err.log.
